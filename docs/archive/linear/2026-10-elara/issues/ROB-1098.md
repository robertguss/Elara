### What exists and what is missing

- FlightRecorder records normalized Core facts/pre/post/intended effects. Session completes recording before shell effect execution (session.ex:1496–1514). A replay match is not full session-policy or provider-request equivalence.
- Context gate (session.ex:1580–1618): computes budget, then frozen → attempt handoff → attempt dispatch; downstream handoff preparation can fail and dispatch can be denied a slot. Those inputs/decisions are not captured. Context (session/context.ex:5–58) depends on resolved context limit/catalog membership, estimate and reserves. Store encoding includes agent_source (session/store.ex:474–482), which recorder normalization drops; original budgets cannot generally be reconstructed from old flights.
- Wake gate (session.ex:2504–2555): paused/active/frozen/recovery guards, queue selection, kind, eight-wake count and continuation exemption precede consumed ask_input. Blocked candidates/count are not recorded. Wake policy needs additional observations, not just another reducer.
- Provider effect normalization (flight_recorder.ex:614–627) omits request.settings, although settings are retained in config/facts. Actual dispatch rewrites agent-source/correlation text (session.ex:1750–1782), outside recorded effects.
- provider_state exclusion is deliberate and tested, not a reason to record private provider data; Context already excludes it. Segments intentionally rebase history or reload tools. Restart recovery precedes a fresh recording. Blind cross-segment equality would reject legitimate behavior.
- Existing replay supports step override and injection. Injection disables baseline comparison; step replay retains first divergence but continues subsequent recorded facts, and segments reseed (flight_recorder.ex:282–365). Later output is not a valid alternative-world outcome. Existing Core-only iteration-limit experiments could be smaller, but would not answer the shell context/wake question.

### Agent + oracle recommendation

Next bounded implementation: add versioned context-gate observations to the existing recorder, plus a small offline cutoff census. Do not move shell policy into Core or build another replay engine. Defer wake observations, request-fidelity expansion and global replay hardening.

Record once using the already-computed live budget, before nested transitions/branch execution: observation/schema/policy-accounting version; original recording_id/sequence/effect_index and segment; resolved limit; estimate_tokens; named reserves; frozen boolean; actual branch (interrupt_frozen, attempt_handoff, attempt_dispatch). Declare recording capability and require coverage for eligible call_provider effects. Preserve the original effect ID, not whichever transition is latest after nested feed calls. Extend both live snapshot and file load/assembly.

Compare E + sum(reserves) >= T, holding recorded accounting fixed; define candidate cutoff T and any integer rounding exactly. This is a cutoff intervention, NOT a different context_limit: changing the latter also changes reserves. The 80% warning is not the dispatch gate. Baseline branch consistency and frozen precedence must be validated. A divergence only establishes a different attempted branch, not successful dispatch/handoff.

### Acceptance for future implementation

1. Scripted public-session fixtures: below/at/above cutoff, frozen precedence, slot denial and failed handoff preparation; original effect linkage and live/file observation equality. No live provider.
2. Independent boundary expectations at T−1/T/T+1; frozen suppresses effective branch divergence even when numeric predicate flips. Slot denial cannot conceal an earlier context-branch divergence.
3. Capture tests for explicit/catalog/default limits, usage-dominated estimates, images and agent-authored inputs; do not reconstruct from normalized history. Preserve private-state exclusion and current default behavior.
4. Legacy flights report unsupported. Missing/truncated observations, wrong/duplicate effect links, absent reserves, unknown semantics and inconsistent baseline never count as successful comparisons. Missing shell observation can be an interrupted capture, not necessarily corruption.
5. Per candidate, stop the assessed prefix at first effective divergence or coverage gap; report excluded suffix/unknown reason. Later segments may only start separately conditional on their recorded seed; no continuity claim across rebase/restart/handoff.
6. Offline census performs no provider/tool execution, slot acquisition, handoff preparation, catalog lookup or history-based budget reconstruction. Report counts and first branch divergence, not quality, token savings or counterfactual outcomes.

Before implementation/measurement, register a bounded refutable hypothesis and fixture plan under the repo lab convention. No experiment was run or validated by this assessment.
