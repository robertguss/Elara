## Description

## Outcome

Run one deterministic cross-class failure matrix over declarative write, typed patch/edit, and opaque shell. Produce comparable evidence that identifies which recovery properties come from the shared durable protocol and which depend on operation-specific observability.

## Context

ER2-1 ([ROB-673](https://linear.app/robert-guss/issue/ROB-673/er2-1-reconcile-declarative-file-writes)), ER2-2 ([ROB-674](https://linear.app/robert-guss/issue/ROB-674/er2-2-reconcile-typed-patch-application)), and ER2-3 ([ROB-675](https://linear.app/robert-guss/issue/ROB-675/er2-3-classify-opaque-shell-execution-truthfully)) deliberately span two inspectable mutation classes and one opaque negative control. This issue is synthesis through executable failures, not another implementation pass. It must expose semantic differences rather than averaging them into a universal “durable tools” claim.

## Scope

* Freeze a matrix before running it with axes for:
  * operation class: write, patch/edit, opaque shell;
  * failure cut: reuse every relevant ER-1 cut and add operation-specific cuts only when justified;
  * receipt state: absent, accepted/running, durable completed success/failure;
  * observable target state: precondition, exact postcondition, conflict, unavailable/not applicable;
  * recovery location: same executor restart versus different executor;
  * identity case: same ID/digest versus conflicting digest reuse.
* Use deterministic barriers/hooks rather than timing sleeps to trigger every cut.
* Assert both safety properties and the exact returned classification.
* Preserve [ROB-667](https://linear.app/robert-guss/issue/ROB-667/fnd-1-freeze-the-er-1-contract-and-baseline-current-behavior)'s crash target/message/storage/restart/evidence model for every reused ER-1 cut; operation-specific rows must freeze the same fields before execution.
* Capture enough event/receipt evidence to diagnose a failed row without rerunning it interactively.
* Run each row repeatedly with fixed seeds/order and record instability as a failure.
* Produce a compact property matrix: at-most-once admission, exact reconciliation, conflict detection, and unavoidable indeterminacy by operation class.

## Non-goals

* Adding new recovery behavior while executing the matrix.
* Making opaque shell satisfy typed-operation postconditions.
* Performance/load benchmarking.
* Distributed multi-node partitions beyond the minimum controller/executor failure topology already under test.
* Declaring product value; that is ER-3.

## Acceptance criteria

* Every predeclared row is an executable deterministic test with an exact expected classification.
* No write or patch row applies the same accepted job twice.
* Same ID/conflicting digest is rejected for all three operation classes.
* Typed operations distinguish durable executor completed from independently observed postcondition_satisfied; exact postconditions support only the preregistered safe action unless authority/fencing proves causal completion.
* Opaque shell remains indeterminate when both durable receipt and explicit postcondition proof are absent.
* Same-executor and different-executor recovery are tested separately; no silent failover violates accepted-job ownership.
* Each row runs at least 20 times (or a justified deterministic equivalent) with no inconsistent classification.
* The Result contains the complete observed matrix and links every unexpected/indeterminate row to captured receipt/events.
* No implementation changes are mixed into this issue except test hooks or evidence capture strictly required to execute the frozen matrix.

## Verification

Create the cross-class matrix and run:

```bash
mix test test/elara/effect/cross_class_matrix_test.exs --seed 0
for i in $(seq 1 20); do mix test test/elara/effect/cross_class_matrix_test.exs --seed 0 || exit 1; done
mix test
mix format --check-formatted
mix compile --warnings-as-errors
```

The Result must include row count, repeated-run count, full observed table, and links to failure artifacts/events.
