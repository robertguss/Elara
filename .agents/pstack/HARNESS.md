# pstack harness adapter

Generated by pstack-portable from pstack **VERSION** (cursor/plugins `997ffc7fe26bdaa6478a14e7f5b8d5f9ed747102`).
Do not edit; re-run sync.

pstack's skills were written for Cursor. Read their Cursor terms through this
table for the harness you are running in. Everything else in a skill applies
unchanged.

**Project instructions win.** Where `AGENTS.md`, `CLAUDE.md` or a project
approval-gates document forbids or gates an action a pstack playbook takes, such
as pushing, merging, landing a stack or deleting worktrees, follow the project
and say which gate stopped you.

**Worktree cleanup.** `poteto-mode/scripts/worktree-audit.sh` reads only Cursor transcripts for its `LAST_CHAT` guard, so outside Cursor that column is always `-`. Treat every `safe` row as `verify-recent-chat`, and confirm with the user before removing any worktree.

## Models per role

- A skill that names "the `<role>` line in `pstack.config.yaml`" means the
  `roles.<slug>` entry, where the slug is the role label lowercased with spaces
  and commas turned into `-`. For example, `feature, refactoring` becomes
  `feature-refactoring`.
- Use the value under your harness key: `amp`, `claude-code`, `codex` or
  `grok` (Grok Build).
- `inherit` (also `auto`, `inherit-parent`) means omit the model so the role
  runs on your own model.
- `model@effort` means pass the model plus that reasoning effort. Claude Code
  and Grok Build have no per-spawn effort, so drop it there.
- A list value is a panel: spawn one subagent per entry, in one message.
- Skills also name Cursor default slugs such as `grok-4.7-xhigh-fast` and
  `claude-opus-5-5-xhigh`. Those don't exist outside Cursor. Never pass them.
  Use the config value, or `inherit` when the role is missing.
- `/setup-pstack` edits `pstack.config.yaml`.
