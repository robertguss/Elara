## Description

## Outcome

Build and review the missing execution-only internal fault capability before confirmatory exposure. Prove every locked v2 baseline and receipts schedule can be injected, recovered, and observed using development qualification fixtures, then freeze adapter/runner/report identities.

## Scope

* Implement the smallest fault-capable internal adapter and checked-in command on top of the neutral runner.
* Support every v2 locked condition, fault type, barrier, process-loss/restart schedule, repetition identity, deadline, evidence field, and workspace reset.
* Keep target behavior and receipt semantics unchanged; adapter mechanisms may orchestrate faults and observation only.
* Establish no-fault equivalence for all included classes and qualification equivalence on separate development fixtures.
* Detect missing/duplicate hooks, inconsistent repetitions, process leakage, dirty fixture resets, evidence gaps, and timeouts as harness failures.
* Freeze source/blob/checksum/config/report-schema identities and categorically forbid v2 confirmatory rows until this issue is Done.

## Non-goals

No execution against v2 confirmatory fault fixtures, scoring, threshold changes, target semantic fixes, result-driven tuning, Lemon fault execution, or dogfood execution.

## Acceptance criteria

Every locked internal schedule is executable for both conditions; injections occur exactly at declared barriers; restarts/reconciliation are deterministic and bounded; evidence validates before scoring; no-fault behavior remains equivalent; no confirmatory target fault output exists; independent review finds no adapter-added recovery semantics.

## Verification

Run adapter unit/integration tests over non-confirmatory development fixtures, process/storage cleanup audits, no-fault equivalence, frozen checksum/schema validation, full tests, format, warnings-as-errors compile, and clean/pushed Git checks.

## Dependencies

Blocked by v2 rematerialization. Blocks immutable v2 internal execution.

## Result

**Canceled — frozen v2 schedule impossibility discovered before adapter construction or confirmatory exposure.**

### Direct invariant audit

* Frozen P05-F3 requires barrier ground_truth_external_mutation_count_eq_1_before_terminal_delivery, exactly one job-attributed external mutation, a postmutation workspace, and no persisted session result.
* P05 instead freezes one pre-dispatch environmental same-file edit with attributed_to_job=false. Its exact-preimage patch must truthfully return error_conflict with expected job external mutations 0 and environmental mutations 1. The P05 job can never reach F3.
* Counting the environmental edit as job-attributed, forcing the conflicting patch, or firing F3 without a mutation would respectively falsify attribution, change target semantics, or fabricate evidence.
* P06-F3 can reach the first-job mutation barrier, but the complete row also conflicts: continuation is frozen to halt after indeterminate/error, while the row expects the full two-job no-fault workspace. Running the second patch would add adapter-owned recovery semantics.

### Independent review

A focused Oracle review independently confirmed both contradictions and the required no-go: [ROB-844](https://linear.app/robert-guss/issue/ROB-844/er3-v2-qualify-and-freeze-the-internal-fault-adapter) cannot meet its acceptance criteria honestly; no adapter may receive a qualifying classification by faking either schedule. Oracle required a fresh preregistration version, future beacon, seed, materialization, and downstream issue identities.
