## Historical finding

Discovered during ROB-1232 (2026-10-03), by the driver. Low priority.

`docs/lab/README.md` ("What a seed fixes") says that rerunning the same seed reproduces a scenario's `choices_digest`. For `session_recovery` it does not. `Observer.report/2` (lib/elara/lab/scenarios/session_recovery.ex, `choices_digest: Elara.Lab.digest({witness.fault, witness.inputs, cleanup.choices})`) hashes `witness.inputs`, which hold per-run accepted-input and persisted ids. At seed 42, tool_running, the smoke, pilot and reproduction runs had identical raw `.cleanup.choices` but three different digests (26abef99…, dc58db96…, e78424c0…).

Why it matters: a digest comparison across reruns would wrongly suggest different choice schedules. Note 005's attempt-4 Limits already records it. Options: hash only seed-determined terms, or qualify the README for scenarios whose digest includes run identities. Either touches the digest, so it is not a measurement change for attempt 4.
