## Description

## Outcome

Implement the single checked-in v4 benchmark entrypoint and qualify the exact orchestration/report path entirely on development fixtures before any held-out fault output.

## Scope

Support qualify, execute, and replay modes; exact-manifest authorization; pinned targets/configuration; fixed fault and no-fault schedules; fresh isolated state; atomic fail-closed checkpoints; immutable raw evidence; canonical report writing; independent scorer replay; hash all semantics-bearing sources/commands/config/artifacts. Exercise the full path on development fixtures and freeze it.

## Non-goals

No v4 confirmatory target row/timing output, B/T claim, target semantic change, Lemon fault execution, dogfood, or result-driven tuning.

## Acceptance criteria

Qualification executes every development fault schedule/repetition and complete timing shape through the same orchestration path; replay is byte-identical; interruption/dirty-output/hash-drift tests fail closed; Oracle review finds no adapter-added recovery; zero confirmatory exposure.

## Verification

Focused integration/failure tests, complete development qualification, source/report hash audit, process/storage cleanup, format, compile, full tests, clean/pushed Git.

## Dependencies

Blocked by v4 materialization. Blocks immutable v4 execution.

## Result

**Disposition: Stop v4 before confirmatory execution.** The complete development-only qualification exposed a preregistration contradiction, so the frozen v4 command was not patched or retried.

* Executed the single checked-in qualify path over all 72 development fault runs and all 72 full-shape development no-fault runs.
* Preserved 288 matched atomic checkpoint events (144 started / 144 completed), with no unmatched run and SHA-256 `e206f46325c420f5c664a0c185b223896e4a745ab598cc7091350769e5878a41`.
* No held-out v4 fault, timing, comparator, dogfood, B, or T evidence was exposed.
* Development score reached `valid=true`, `status=Fail`, `B=12`, `T=3`, `B−T=9`; knowledge/safe-action, no-fault correctness, and timing passed. Terminal convergence failed only for the nine baseline F4 repetitions because the frozen row-level causal-terminal expectation applied `true` to both conditions even though baseline F4 correctly has manual recovery, no causal proof, and nil terminal convergence while receipts F4 has automatic causal terminal proof.
* Canonical report writing additionally exposed non-JSON tuple diagnostics. Qualification authorization also required only `valid`, not exact `status=Pass`.
* Oracle concluded causal-terminal applicability must be condition-specific: F1–F3 false/false; F4 baseline=false and receipts=true. It also requires canonical JSON diagnostics and Pass-only qualification authorization.
* The base amendment rule requires a fresh version and future seed for this factual preregistration correction. V4 therefore stops; its checkpoint is development failure evidence, not v5 qualification evidence.
