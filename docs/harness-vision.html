HarnessA BEAM-Native Fabric for Software Work

A bold architectural direction for evolving Harness beyond a conventional coding-agent CLI—toward durable missions, supervised actors, isolated workspace cells, causal replay, and evidence-bearing software delivery.

Software work is a durable causal graph interpreted by supervised actors, executed in isolated cells, and accepted through evidence-bearing gates.

01 · The thesisNot Pi in Elixir

Harness should not merely reproduce today’s local coding agents with GenServers, nor stop at placing familiar agents inside cloud sandboxes. The larger opportunity is a durable, supervised runtime for software work itself.

The process is not the agent. The durable history and identity are the agent; a BEAM process is its current incarnation.

Models become replaceable reasoning components. Sandboxes become replaceable execution bodies. The durable mission, effects, evidence, identity, and causal history become the product.

02 · FoundationsDesign principles

Identity

Durable entity, temporary process

A logical entity has a stable ID, journal, snapshot, causal parent, fenced lease, and pending receipts. It may have zero or one live process.

Boundary

BEAM as control plane

OTP owns lifecycle, ordering, cancellation, coordination, and observability. Cells, databases, and object stores own isolation and durable material.

Reliability

Supervision is not durability

A supervisor restarts an interpreter. Effect receipts and reconciliation recover external work.

Truth

Uncertainty is first-class

Distinguish not submitted, accepted, completed, failed, cancelled, and indeterminate. Never invent certainty.

Quality

Evidence, not confidence

Consequential work carries claims, artifacts, receipts, tests, versions, uncertainty, and approvals.

Coordination

Bounded Missions, not swarms

Use typed objectives, capabilities, deadlines, deliverables, and gates rather than endless peer conversations.

Durable identity and activation

Durable entity
    │
    ├── snapshot
    ├── journal tail
    ├── pending effect receipts
    └── causal links
           │
           ▼ activation
      ┌───────────┐
      │ GenServer │  current embodiment
      └───────────┘
           │
           ▼ passivation / crash
     durable entity remains

Idle entities passivate. Commands and subscribed events activate them on any trusted control node that acquires the ownership lease and fencing epoch.

Important: Distributed Erlang can be useful inside one trusted control-plane island. It should not cross tenant, worker, or hostile execution boundaries.

03 · DelegationSub-agents become Missions

Running a tool in another process does not reduce context if its raw output still enters the parent transcript. A real sub-agent has a separate model context and tool history, performs a bounded objective, and returns a compact but complete work product.

Process-isolated tool

Runtime separation only

Runs elsewhere and returns raw output. The parent still absorbs that output and receives no semantic isolation.

Mission

Context and responsibility boundary

Own transcript, objective, deadline, capabilities, deliverable, evidence, continuation ID, and parent-controlled cancellation.

Session-owned delegate

The model-facing operation should be a built-in Session effect, not an ordinary plugin. The Session already owns the parent identity, turn interruption, capability inheritance, causal recording, child retention, and recursion policy.

Input protocol

{
  "task": "Trace plugin reload cancellation and identify any race",
  "context_mode": "fresh"
}
{
  "child_session_id": "child-123",
  "task": "Expand on the lease race and quote the relevant functions"
}
fresh · task onlyminimal · latest user requestinherited · settled transcriptcontinuation · child history

The recommended default is fresh. The delegated task should be self-contained. Inherited history must stop before the unresolved parent delegate call.

Child policy for v1

  • Same repository instructions, working directory, base tools, capability ceiling, workspace, and router.
  • Fresh child-owned instances of the same plugins; plugin state is not shared.
  • No delegate tool, giving a hard recursion depth of one.
  • One active delegation per parent.
  • Parent interruption interrupts and stops the child.
  • A dedicated absolute deadline, longer than an ordinary tool timeout.

No blind result truncation

A child’s conclusion must never be sliced at an arbitrary byte boundary. The complete answer is persisted in the child first. The parent receives one of three explicit delivery modes.

Full

Complete

The intact result fits the parent’s result budget.

Summary

Semantically compressed

The same child creates a complete summary; the original remains retained.

Metadata only

Details retained

Compression could not fit safely. Return status, child ID, and explicit more_available.

Child completes work
        │
        ▼
Persist complete answer in child transcript
        │
        ▼
Fits parent budget? ── yes ──▶ delivery: full
        │ no
        ▼
Ask child once for semantic compression
        │
        ▼
Fits safely? ── yes ──▶ summary + child ID
        │ no
        ▼
metadata_only + child ID + more_available

A high emergency transport ceiling still exists because context is finite, but it is an invariant rather than the summarization mechanism. The envelope must fit before generic tool-output truncation can activate.

ChildSession as shared substrate

start child
ask child
continue child
interrupt child
stop or passivate child

delegate owns model-facing single-child policy. Coordinator retains fan-out, candidate comparison, judges, reducers, worktrees, and aggregate budgets. Both use the smaller lifecycle primitive.

04 · SystemsLayered target architecture

Plane 1 · Durable truth

Journal

Entity facts

Commands, accepted facts, transitions, effect intents, completions, migrations, and approvals.

Content graph

Immutable artifacts

Prompts, transcripts, patches, outputs, reports, and environment manifests addressed by digest.

Projection

Queryable views

Status, lists, trees, dashboards, search indexes, and durable event feeds.

validate fact
   │
   ▼
run pure reducer
   │
   ▼
atomically append:
  fact + transition + events + effect intents
   │
   ▼
dispatch effects separately
   │
   ▼
append completion or reconciliation facts

Historical outbox entries are not blindly dispatched just because a process restarted. Local Harness can use an embedded journal; a hosted deployment can use a transactional database plus object storage.

Plane 2 · Activated actors

Project
├── Sessions
│   ├── Missions
│   │   └── Child sessions
│   └── In-flight job proxies
├── Workspace leases
├── Verification gates
└── SDLC reactors

This is a logical ownership graph, not necessarily one physical OTP link tree. Processes are supervised by type on the node currently holding the durable entity lease.

Plane 3 · Remote workspace cells

submit(job_id, operation_digest, workspace_epoch, policy, deadline)
accepted(receipt)
query(job_id)
stream(job_id, cursor)
cancel(job_id)
result(job_id, outcome, artifact_digests)
planned → submitted → accepted → running
        → completed | failed | cancelled | indeterminate

A cell combines an immutable base, writable overlay, fenced mutation lease, resource limits, secret and egress policy, durable job ledger, resumable stream, and patch/artifact export. Its provider can be local, container, VM, Kubernetes, hosted orb, or customer runner.

Plane 4 · Evidence and provenance

Consequential results retain claims, source snapshot, patch digest, model and tool versions, commands and receipts, tests and reviews, uncertainty, approvals, and policy versions. Independent verifiers receive the claim and evidence—not the candidate’s entire persuasive transcript.

Plane 5 · Gateways and collaboration

CLI, IDE, web control room, APIs, CI adapters, webhooks, and approval queues become views onto durable entities. Multiple principals can observe and propose, but each entity preserves one serialized command order.

Plane 6 · Project Reactors

Mostly passivated repository automata wake for issues, PRs, CI, deployments, incidents, dependency changes, reviews, and schedules; create bounded Missions; wait for people or systems; and recover after machine loss.

06 · FrontierSpeculative directions

Repository memory as a provenance graph

Store architectural decisions, invariants, ownership, failed approaches, incidents, and contracts as facts linked to exact source snapshots and evidence. Facts become stale when their supporting code changes. Context becomes a small provenance-bearing capsule rather than an unbounded vector search.

Software immune system

Mostly sleeping sentinels watch dependency risk, performance, flakes, security-sensitive changes, API drift, and invariants. They open bounded investigation Missions and propose containment, rollback, or repair through policy gates.

Many-worlds development

Fork several snapshots for genuinely uncertain architecture work, assign competing hypotheses, run identical evaluation suites, compare evidence, and retain losing branches as searchable knowledge.

Agent portfolios

Schedule by measured capability—search model, implementation model, analyzer, fuzzer, device lab, verifier—rather than permanent anthropomorphic personalities. Learn cost, latency, and success distributions from evidence.

Counterfactual CI

Ask which causal assumption changed, whether a prior policy would accept the work, which historical patches relied on a broken invariant, and whether relevant Missions can replay against a changed dependency.

Executable governance

Versioned policies govern secrets, tools, approvals, autonomy, risk, and evidence. A blocked action returns a causal explanation rather than an opaque denial.

Incident-to-patch continuity

Symptoms, investigation, rollback, diagnosis, patch, tests, release, and postmortem become one causal graph surviving shifts, handoffs, environments, and process failures.

07 · ReliabilityFailure semantics

FailureRequired behavior
Session process or VM diesNew owner rehydrates the entity and reconciles pending receipts.
Provider call disappearsRecord the lost attempt; retry only as an explicit new, budgeted attempt.
Worker disconnects before acceptanceResubmit the same job ID elsewhere when policy permits.
Worker disconnects after accepting mutationQuery the same durable job; report indeterminate if proof is unavailable.
Parent dies while child runsDurable Mission retains ownership; recovered parent awaits, continues, or cancels.
Workspace owner changesAdvance fencing epoch so stale workers cannot mutate.
Human client disconnectsSession continues; reconnect from a durable cursor.
Reducer or plugin changesExisting entities stay pinned or undergo an explicit recorded migration.
Non-negotiable: OTP restart intensity is not a work retry policy.

08 · GuardrailsSeductive ideas to reject

Trust

Naive distributed Erlang

PIDs, cookies, atoms, code loading, and transitive connectivity are not a hostile-boundary protocol.

Coordination

Autonomous swarms

Unbounded peers amplify cost, correlated hallucination, unclear ownership, and cancellation difficulty.

Modeling

Process-per-everything

Processes model active ownership, not durable records, indexes, artifacts, or permanently idle repositories.

Recovery

Supervision as durability

Restarting restores neither durable state nor knowledge of an external mutation.

Mutation

Silent failover

Never rerun uncertain mutation elsewhere unless the same durable job is provably deduplicated.

Workspace

Shared writable concurrency

Concurrent work branches and exchanges artifacts; it does not race over one filesystem.

Data

PubSub as truth

Streams deliver projections. The durable journal establishes what happened.

Claims

Replay as proof

Replay proves reducer consistency, not that an external result was correct.

Evolution

Invisible hot upgrade

Pin generations and record migrations so every decision remains reproducible.

History

CRDT transcript merging

Conversational branches rarely merge meaningfully. Reconcile results and artifacts instead.

Promises

“Exactly once” marketing

Promise receipts, deduplication where possible, reconciliation, and explicit uncertainty.

09 · ScienceExperiments that can falsify the vision

These should be vertical product slices, not infrastructure demonstrations.

1 · Crash-everywhere recovery

Kill control state before submission, after acceptance, during mutation, after result arrival, during delegation, and while awaiting approval.

Pass: one confirmed mutation or explicit indeterminate state, never silent duplication. Falsifies: recovery needs ad hoc phase repair or cannot distinguish unsubmitted from uncertain work.

2 · Delegation quality benchmark

Compare single-agent work with delegated research, implementation, and independent verification over 30–50 real tasks. Measure correctness, parent context, latency, cost, follow-up value, and unsupported claims.

Pass: meaningful correctness or context gains. Falsifies: if only cost rises, retain Missions primarily for isolation and verification.

3 · Durable mutation receipt

Submit one marker-producing mutation under the same job ID while repeatedly killing control processes and transport. No duplicate is allowed while worker durability remains; loss of proof must become indeterminate.

4 · Cross-entity causal replay

Record parent → child → job → artifact → verifier → result. Trace one patch hunk to origin, then inject verifier failure and replay without running external tools.

5 · Hostile workspace cell

Attempt symlink escape, host access, secret discovery, unrestricted egress, fork bomb, disk exhaustion, and stale-epoch mutation. The actual isolation boundary must block or bound them.

6 · Durable collaborative control room

Two humans and one agent disconnect, reconnect, compete for stale control, approve work, and survive VM loss while preserving ordering and events.

7 · One real Project Reactor

Use duplicate and out-of-order CI events to run one logical diagnosis, isolated patch, verification, approval, and external result without duplication.

10 · SequenceThree development horizons

Durable semantics on one node

Prove recovery before clustering.

  1. Extract ChildSession and add Session-owned delegate.
  2. Use semantic result delivery and durable child continuation.
  3. Add stable entity, transition, effect, and causation IDs.
  4. Introduce a journal and effect outbox.
  5. Recover Session from snapshot plus facts.
  6. Persist cursors, parent-child links, and large artifacts.
  7. Model effect acceptance, completion, cancellation, and reconciliation.
  8. Rebuild Coordinator on ChildSession.
  9. Pin plugin generations and inject crashes at every boundary.
Success gate: crash recovery and delegation benchmarks pass.

Trusted distributed control plane + isolated cells

  1. Durable worker job protocol with query, stream, cancel, and deduplication.
  2. Real container or VM workspace-cell provider.
  3. Snapshot overlays, mutation leases, and fencing epochs.
  4. mTLS and short-lived capability grants.
  5. Durable Missions, evidence bundles, and verification gates.
  6. Control-room roles, approvals, and durable cursors.
  7. Multi-node entity activation inside a trusted BEAM island.
Success gate: partition, stale-writer, and hostile-cell experiments pass.

Supervised SDLC fabric

  1. Project Reactors and issue, PR, CI, deployment, dependency, and incident adapters.
  2. Human approval queues and policy-defined verification.
  3. Cross-repository Missions and artifact handoffs.
  4. Project and organization cost, concurrency, token, and risk budgets.
  5. Versioned workflow, policy, plugin, and reducer migrations.
  6. Provenance-aware repository memory and Shadow Runtime.
  7. Multi-tenant isolation, retention, audit, and operations.

If multi-agent benchmarks fail, this still yields a durable single-agent, verification, and SDLC automation platform. Swarms are optional; recoverable work and evidence are not.

These products share versioned protocols and entity semantics, not necessarily one runtime or deployment artifact.

The sharpest formulation

The conventional model says: an agent is a model loop with tools.

Harness can say: software work is a durable causal graph interpreted by supervised actors, executed in isolated cells, and accepted through evidence-bearing gates.

That is not simply another agent harness. It is a different theory of how humans, models, tools, environments, and software-delivery systems can work together.
