## Description

Selected 2026-10-08 by the owner (Robert) as the next bounded slice under [ROB-1106](https://linear.app/robert-guss/issue/ROB-1106/daily-driver-usability) daily-driver usability, after grep/glob ([ROB-1342](https://linear.app/robert-guss/issue/ROB-1342/workspace-search-tools-grep-and-glob) / PR #67).

Goal: a transient provider failure (rate limit, overload, 5xx, dropped connection or stream before any output) is retried with bounded backoff instead of ending the turn, so daily sessions survive flaky APIs. Non-transient errors (auth, invalid request, context too long) still fail immediately and clearly.

Design first, subtract first: before code, write a short plan at the top of the PR covering which existing provider/stream/error code this reuses, where the single retry point lives so every provider gets it, what counts as retryable, and whether a retry is ever allowed after partial streamed output (default: no; once output or a tool call has been emitted, surface the error rather than replay, so nothing is duplicated). Honor Retry-After when present.

Scope: bounded attempts and total wait (configurable with sane defaults), jittered exponential backoff, cancellation (user interrupt / session stop) aborts the wait promptly. Retry attempts visible to the operator (TUI status line and recorded in the session/FlightRecorder log) without inventing new persistence formats beyond what's needed. Works for every configured provider via the shared path.

Acceptance: scripted tests with a simulated provider (no network, no credentials) covering: retry-then-success; exhaustion with the final error surfaced; Retry-After honored; non-retryable errors not retried; failure after partial output not replayed; cancellation during backoff; no duplicate messages/tool calls in the session record. Targeted tests, compile/format, native checks and broader affected coverage pass. User-path drive via the repo's verify harness where it applies.

Non-goals: provider fallback/switching, model routing, new providers, UI redesign, protocol version/actor changes. No real-model or account-backed run. Preserve LAB-3 pause, LAB-8 gate and owner gates. Deliver on an issue branch via PR with green required checks; leave merge for the owner. Done only after merge.

One retry point in `Elara.Session.Core`, because it owns the only `call_provider` effect, so every configured provider gets it. `Elara.Provider.Retry` classifies by error kind and status and sizes the window. Retryable: 408/425/429/5xx (including 509 and 529) and transport drops. Not retryable: auth, invalid request, entitlement, context/concurrency limits, malformed responses, crashes. Once streamed text or a typed public part exists, the error is surfaced and the attempt is not replayed. `Retry-After` is waited exactly and refused, not shortened, past the remaining budget. Interrupt or steer cancels a pending wait.
