## Outcome precedence

Evaluate **Stop first**, then Continue, then Narrow, then Pivot under the rules below. No intuition, code investment, or reinterpretation may override a higher-precedence result.

### Stop

Choose Stop if any is true:

* duplicate external marker mutation occurs, or a callback is reinvoked without declared atomic ID/digest mutation deduplication;
* false success or false error occurs;
* same ID/conflicting digest is admitted;
* an accepted mutation silently executes on a replacement executor;
* the no-fault exactly-one control fails;
* no nonempty preregistered scope/subset satisfies all of its safety, truth, and liveness requirements.

Cancel every invalidated M2/M3 issue and link this gate as the reason.

### Continue

Choose Continue only if all are true:

* all three controls pass;
* all eight observed rows match every frozen controller/executor/workspace/history/session expectation;
* every row converges within its frozen bound to a truthful knowledge state and safe next action, and every row with surviving admissible causal terminal evidence converges to `completed` or `failed`;
* every indeterminate row lacks admissible causal terminal evidence and names both that missing fact and all surviving nonterminal/noncausal evidence;
* recovery is job-evidence-driven and does not use transcript repair;
* the sidecar ownership preserves the pure reducer boundary.

Unblock the first M2 issue according to native relations and mark only it Todo.

### Narrow

Choose Narrow only if:

* every safety/control requirement passes; and
* at least one nonempty subset preregistered in [ROB-667](https://linear.app/robert-guss/issue/ROB-667/fnd-1-freeze-the-er-1-contract-and-baseline-current-behavior) **before implementation** satisfies every truth and liveness requirement for that subset; and
* the full ER-1 scope does not qualify for Continue.

Select the first passing subset in [ROB-667](https://linear.app/robert-guss/issue/ROB-667/fnd-1-freeze-the-er-1-contract-and-baseline-current-behavior)'s frozen precedence order, state its exact surviving claim, cancel incompatible M2/M3 work, and create no broader replacement work.

### Pivot

Choose Pivot only if:

* safety/control requirements pass;
* receipt semantics demonstrate a nonempty viable scope;
* a concrete observed row proves the current sidecar ownership contaminates `Elara.Session.Core` phases or another named ownership invariant; and
* no preregistered narrower subset resolves that contradiction.

Name one smallest replacement boundary experiment, keep M2 blocked, and cancel superseded work. Pivot may not relabel a safety or liveness failure.
