## Description

## Outcome

Materialize the preregistered ER-3 corpus after GATE-2 selects a semantic scope: 8–12 immutable offline coding tasks producing 12–20 scored fault rows, with exact plans, fixture digests, fault schedules, expected invariants, disqualifiers, and evidence requirements. Do not implement or run the benchmark harness here.

## Context

[ROB-772](https://linear.app/robert-guss/issue/ROB-772/fnd-2-preregister-evidence-thresholds-and-comparator-suitability) froze the candidate pool/sampling frame, conditional GATE-2 selection rules, held-out/exposure policy, classifications, thresholds, eligible narrower scopes, amendments, and comparator suitability before target implementation. GATE-2 selects Universal or Typed-only. This issue mechanically materializes the corresponding locked branch without selecting favorable rows from observed performance.

## Scope

* Apply [ROB-772](https://linear.app/robert-guss/issue/ROB-772/fnd-2-preregister-evidence-thresholds-and-comparator-suitability)'s exact selection algorithm/seed and conditional GATE-2 branch.
* Select 8–12 small tasks from immutable repository snapshots, producing 12–20 scored fault rows.
* Cover the applicable scope among create/overwrite, one-file edit, multi-file change, typed mutation plus verification, opaque command with unprovable effect, build/test command, and concurrent conflict.
* Define fixed provider responses/tool-call plans with `Elara.Provider.Scripted` for Elara targets.
* Freeze for every row:
  * task/fixture commit and initial digest;
  * operation plan and expected no-fault final digest;
  * crash target/failpoint, delivered/dropped messages, surviving storage, restart order, admissible evidence, observation deadline, and convergence bound;
  * expected primary recovery classification and safety invariants;
  * evidence/artifact fields required by the neutral runner;
  * semantic-equivalence requirements for baseline, receipt, and eligible external adapters.
* Version the corpus manifest, fixture membership, plans, fault-row IDs, and checksums.
* Preserve development/regression/held-out exposure labels.

## Non-goals

* Implementing the runner, scorer, fixture reset, target adapters, or fault hooks.
* Running no-fault or fault rows.
* Changing [ROB-772](https://linear.app/robert-guss/issue/ROB-772/fnd-2-preregister-evidence-thresholds-and-comparator-suitability) formulas, thresholds, selection rules, eligible Narrow scopes, comparator, or amendments.
* Using live model quality or claiming SWE-bench/general statistical comparability.

## Acceptance criteria

* Manifest contains 8–12 tasks and 12–20 uniquely identified scored fault rows selected exactly by [ROB-772](https://linear.app/robert-guss/issue/ROB-772/fnd-2-preregister-evidence-thresholds-and-comparator-suitability).
* Every task is runnable without network or live credentials once the neutral runner exists.
* Every fixture repository commit/digest, plan, fault schedule, expected invariant/classification, evidence field, and no-fault final digest is frozen.
* Each row contains the full [ROB-667](https://linear.app/robert-guss/issue/ROB-667/fnd-1-freeze-the-er-1-contract-and-baseline-current-behavior)-style fault/durability model; no row relies on timing sleeps.
* Safety disqualifiers and semantic-equivalence rules are explicit and cannot be offset by scores.
* Exposure labels prove inspected development cases are not represented as held out.
* Applicable plans can be mapped by baseline, receipt, and external adapters without requiring identical internal seams; non-equivalence is a declared adapter outcome.
* No target fault result is produced or inspected in this issue.
