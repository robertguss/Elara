## Description

## Outcome

Build and independently review the execution-only internal fault capability on separate development qualification fixtures. Prove every locked v3 baseline/receipts schedule can be injected, recovered, and observed, then freeze adapter, runner, command, configuration, evidence, and report identities before confirmatory exposure.

## Scope

Implement the smallest adapter on the neutral runner; support every condition/fault/barrier/restart/repetition/deadline/evidence field and multi-step continuation contract; keep target recovery semantics unchanged; establish no-fault equivalence; detect missing/duplicate/late hooks, dirty resets, leaked processes, inconsistent repetitions, evidence gaps, and timeouts as harness failures; categorically forbid v3 confirmatory rows during qualification.

## Non-goals

No v3 confirmatory fault fixture execution, scoring, threshold/target changes, adapter-added recovery, Lemon fault execution, or dogfood.

## Acceptance criteria

Every compatible locked schedule is executable for both conditions at the declared barrier; process loss/restart/reconciliation is deterministic and bounded; all evidence validates before scoring; no-fault semantics remain equivalent; independent review finds no adapter-added recovery; zero confirmatory target fault output exists.

## Verification

Run adapter unit/integration tests over development fixtures, process/storage cleanup audits, no-fault equivalence, complete fixed repetition qualification, frozen checksum/schema validation, full tests, format, warnings-as-errors compile, and clean/pushed Git checks.

## Dependencies

Blocked by v3 rematerialization. Blocks immutable v3 internal execution.

## Result

Completed in [implementation commit 103a275](<https://github.com/robertguss/elixir-harness/commit/103a275>) and finalized in [authorization correction 1d57c7e](<https://github.com/robertguss/elixir-harness/commit/1d57c7e>).

* Derived a 12-row development-only matrix covering write/patch/shell × F1–F4, with 3 fixed repetitions for baseline and receipts: 72 fault runs total.
* Final qualification: all 72 records validated consistently; 6/6 no-fault runs equivalent; knowledge convergence 17–52 ms; terminal convergence 31–52 ms; zero safety disqualifiers or harness errors.
* Exposure: 0 held-out v3 confirmatory fault runs and no B/T calculation. Development qualification remains the default-only mode.
* The frozen adapter now exposes one explicit confirmatory activation seam. * Baseline barriers remain explicitly adapter-observed nearest seams, N/A/non-equivalent to receipt-native seams. Baseline receipt counters remain N/A; callback entry/return counts come from wrapper instrumentation rather than workspace inference.
