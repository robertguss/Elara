## Description

## Outcome

Establish the truthful durability boundary for arbitrary shell execution. Prove which outcomes can be recovered from durable executor receipts and which must remain indeterminate because an opaque command has no machine-checkable postcondition.

## Context

Elara currently exposes arbitrary shell through `System.shell/2`. The controller can observe a transport reply, timeout, or worker loss, but cannot infer all side effects of a command from its text or exit status. ER2-1 ([ROB-673](https://linear.app/robert-guss/issue/ROB-673/er2-1-reconcile-declarative-file-writes)) and ER2-2 ([ROB-674](https://linear.app/robert-guss/issue/ROB-674/er2-2-reconcile-typed-patch-application)) test typed, inspectable mutations; this issue is the negative control that prevents those guarantees from being overgeneralized.

Begin only if GATE-1 ([ROB-672](https://linear.app/robert-guss/issue/ROB-672/gate-1-decide-er-1-continue-pivot-narrow-or-stop)) records **Continue**.

## Scope

* Model current `bash` execution as an opaque operation within the ER-1 job/receipt protocol.
* Define and test the distinction between:
  * controller intent plus the frozen pre-acceptance query schedule can prove no acceptance; durable executor evidence proves accepted/nonterminal, completed success, or completed failure;
  * receipt missing while command start/effects are unknown;
  * controller reply lost while durable completion survives;
  * worker or ledger lost while the OS command may have run;
  * command timeout versus confirmed process termination.
* Demonstrate with commands whose externally visible effects cannot be inferred safely from command text.
* Keep opaque shell's causal terminal outcome indeterminate whenever no admissible durable causal terminal receipt survives. An explicit operation-specific postcondition may establish current state and a safe next action, but proves executor completion only when the operation atomically emits exclusive job-ID/digest-bound causal evidence or equivalent fencing.
* Keep durable executor completed, independently observed side effects/postconditions, and session classification distinct.
* Define the narrow adapter seam by which future typed commands may supply their own preconditions/postconditions without parsing shell syntax.
* Record whether process lifetime can escape the BEAM port and what that means for receipts.

## Non-goals

* Parsing shell commands to infer idempotency.
* Sandboxing arbitrary commands, tracing every syscall, or implementing distributed OS-process control.
* Pretending exit code 0 proves all intended effects or that a timeout proves no effect.
* Automatically retrying an opaque command after an ambiguous failure.
* Building typed adapters beyond the smallest fixture needed to show the seam.

## Acceptance criteria

* Lost controller reply plus surviving durable completion converges to the recorded exit/result without rerunning the command.
* Same ID/digest is never admitted as a second execution; changed command/cwd/env/workspace/authority under the same ID is rejected.
* Missing receipt after possible command execution remains indeterminate; no source-code or command-string heuristic upgrades it to success or failure.
* Timeout, worker death, executor restart, and ledger loss each have an observed test result and explicitly state whether the child OS process is known terminated.
* Tests include at least one command that mutates more than one observable resource or has a non-filesystem effect to invalidate simplistic file checks.
* Opaque shell is not silently retried on another worker.
* A typed-adapter fixture demonstrates how explicit postconditions can establish current state and a safe next action without changing arbitrary shell semantics or fabricating causal completion.
* The Result states the maximum defensible claim for opaque commands in one sentence.
