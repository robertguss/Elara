## Description

## Outcome

Add a test-only durable executor ledger with explicit `submit(job_id, digest, operation)` and `query(job_id)` semantics. Acceptance and terminal completion survive executor restart; duplicate and conflicting submissions are deterministic; protocol ordering matches [ROB-667](https://linear.app/robert-guss/issue/ROB-667/fnd-1-freeze-the-er-1-contract-and-baseline-current-behavior) exactly.

## Context

The current worker validates one socket request and spawns a linked process. Socket closure kills the job. There is no durable acceptance fact, acceptance reply, completion receipt, or query path.

[ROB-668](https://linear.app/robert-guss/issue/ROB-668/er1-1-commit-stable-job-identity-digest-and-controller-intent) supplies the controller-owned job identity/digest. [ROB-667](https://linear.app/robert-guss/issue/ROB-667/fnd-1-freeze-the-er-1-contract-and-baseline-current-behavior) freezes this executor order:

`receipt → durable acceptance commit → acceptance reply → callback attempt → external mutation → durable completion commit → completion reply`.

Acceptance reply precedes mutation. This is a test executor contract, not production remote-worker migration.

## Scope

* Extend the ER-1 request value with controller-owned `job_id` and `operation_digest`.
* Durably record exactly one digest-bound `accepted` fact before acceptance reply and before mutation.
* Emit the acceptance reply, then record each callback attempt separately from external mutation. After uncertain accepted execution, do not reinvoke a callback with a non-deduplicated external mutation; reinvocation is allowed only when the operation atomically deduplicates and causally receipts the entire mutation by ID/digest.
* Durably record `completed` or `failed` plus result/receipt digest before completion reply.
* Define `submit` for unseen, duplicate same-digest accepted/nonterminal, duplicate same-digest terminal, and conflicting-digest jobs.
* Define `query` for unknown, accepted/nonterminal, completed, failed, and explicit proof loss.
* Reopen accepted and terminal state after executor process and storage-connection restart.
* Add deterministic failpoints immediately before/after receipt, acceptance commit, acceptance reply, mutation callback, completion commit, and completion reply.
* Preserve the last proven fact when proof is lost; never turn accepted alone into completion.

## State vocabulary

ER-1 executor records only:

* `accepted` — this job ID/digest is owned; mutation completion is not proven;
* `completed` — durable causal completion and result evidence;
* `failed` — durable causal failure and error evidence.

Unknown/missing proof is a query observation, not a fabricated terminal state. Cancellation is outside ER-1.

## Non-goals

* Session/marker integration.
* Automatic resubmission or failover to another executor after acceptance.
* Cancellation, leases, queueing, scheduling, production protocol compatibility, or exactly-once marketing.
* Reusing conversation/transcript storage as executor truth.

## Acceptance criteria

* First unseen submit commits one accepted identity before acceptance reply and mutation callback.
* Same ID/digest has one admission. Duplicate submit/query returns existing accepted or terminal evidence and does not itself invoke the callback. Any accepted-job callback reinvocation follows the frozen operation rule and is forbidden without atomic ID/digest mutation deduplication and causal receipts.
* Same ID/different digest is rejected without callback invocation.
* Acceptance and terminal evidence survive executor/storage restart.
* Acceptance reply is impossible before acceptance commit; mutation is impossible before acceptance reply.
* Completion reply is impossible before terminal commit.
* A lost acceptance reply is recoverable as `accepted` when acceptance proof survives; a lost completion reply is recoverable as `completed` or `failed` only when corresponding durable causal terminal proof survives.
* Accepted alone never reports success/failure and never authorizes failover or an unprotected callback retry; missing causal terminal proof follows [ROB-667](https://linear.app/robert-guss/issue/ROB-667/fnd-1-freeze-the-er-1-contract-and-baseline-current-behavior)'s frozen classification/action and never triggers failover.
* Every [ROB-667](https://linear.app/robert-guss/issue/ROB-667/fnd-1-freeze-the-er-1-contract-and-baseline-current-behavior) executor failpoint is deterministic and test-only; no sleep orders a crash.
* Executor completed, independent postcondition satisfaction, and session classification remain separate.

### Ledger and state contract

The executor owns a separate SQLite database/connection with schema/user version 1, `journal_mode=WAL`, `synchronous=FULL`, and `busy_timeout=1000`. `job_id` is the primary key and the row also binds the controller SHA-256 `operation_digest` and logical `executor_id`. Transactions atomically commit admission, callback-attempt, and terminal facts.

| Query observation | Durable row | Counts `admission / callback_attempt / terminal` | Result evidence |
| -- | -- | -- | -- |
| `unknown` | none | `0 / 0 / 0` | none |
| `accepted` | accepted before reply | `1 / 0 / 0` | none; one same-owner continue is allowed |
| `accepted` | callback invocation was attempted | `1 / 1 / 0` | none; reinvocation and failover are permanently forbidden |
| `completed` | terminal success | `1 / 1 / 1` | `{:ok, payload}` plus versioned deterministic result digest |
| `failed` | terminal error | `1 / 1 / 1` | `{:error, payload}` plus versioned deterministic result digest |

Row decoding revalidates IDs, digest form, versions, count/state consistency, result kind, and result digest. Terminal result and digest are committed in the same transaction.

### Submit, query, and continue

* First unseen same-owner `submit(job_id, digest, operation)` durably returns `{:accepted, record}`; submit itself never invokes the callback.
* Duplicate same-ID/same-digest submit returns existing accepted/completed/failed evidence with admission count still 1 and ignores the duplicate operation.
* Same ID/different digest returns `{:error, :digest_conflict}`; same accepted identity through another logical executor returns `{:error, :wrong_executor}`.
* `query(job_id)` returns `:unknown` or the exact durable accepted/completed/failed record and never invokes a callback.
* `continue` is the sole invocation transition. It requires the accepting executor identity, matching digest, and accepted attempt count 0. Attempt count 1 returns `:callback_already_attempted`; terminal state returns `:already_terminal`.
* After owner restart the test supplies the same digest/operation explicitly; an opaque closure is intentionally not persisted.

### Protocol-order and restart evidence

The GenServer owns the Exqlite connection and enforces:

`receipt → accepted commit → acceptance reply → callback-attempt commit → callback → external mutation → terminal commit → completion reply`.

The exact deterministic executor barriers are:

* `:after_receipt_before_accept_commit`
* `:after_accept_commit_before_accept_reply`
* `:after_accept_reply_before_callback`
* `:after_external_mutation_before_completion_commit`
* `:after_completion_commit_before_completion_reply`

Tests block at each barrier, kill the owner without sleeps, reopen the same on-disk database, and query it. Results are respectively unknown; accepted with attempt 0; accepted with attempt 0 and one permitted same-owner continue; accepted with attempt 1 and no permitted reinvocation; and completed with the completion reply lost. A replacement logical executor can query but cannot submit/continue the accepted job.

No-fault and duplicate controls separately assert admission count 1, callback-attempt count 1, terminal count 1, and independently observed external-mutation count 1. Failed callback results and callback crashes persist as failed evidence. Request wire values now carry both controller-owned fields while decoding remains compatible when both fields are absent; mutating Session requests receive the identity committed by [ROB-668](https://linear.app/robert-guss/issue/ROB-668/er1-1-commit-stable-job-identity-digest-and-controller-intent) and nonmutating requests remain unchanged.
