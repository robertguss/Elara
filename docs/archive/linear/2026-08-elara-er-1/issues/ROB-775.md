## Description

## Outcome

Execute only the preregistered, semantically equivalent external-runtime fault rows using the reviewed adapter and pinned comparator. Produce either a valid comparative report or the explicit result **Insufficient comparability**; unavailable seams never count for or against Elara.

## Context

[ROB-680](https://linear.app/robert-guss/issue/ROB-680/er3-3-test-a-comparable-agent-runtime) proves no-fault equivalence and freezes the row-level comparability table from capability and fault-hook evidence. [ROB-681](https://linear.app/robert-guss/issue/ROB-681/er3-4-dogfood-real-coding-tasks-with-scheduled-failures) freezes dogfood task selection before any target fault outcomes. This issue performs immutable execution only.

External evidence is secondary. It tests whether observed recovery value is unique to Elara's implementation, not whether BEAM is superior.

## Scope

* Verify preregistration, comparator commit/config, external build, adapter, corpus, runner, scorer, and eligible-row checksums.
* Re-evaluate only environmental availability, not semantic eligibility, before execution.
* If the locked floor is met, execute every eligible external fault row in fixed recorded order and capture raw machine-readable evidence.
* The floor requires no-fault equivalence for every included operation class and at least three equivalent fault rows spanning at least two fault types.
* If the floor is not met, record **Insufficient comparability**, list exact missing capabilities/hooks, and make no comparative claim.
* Run the unchanged scorer only over the locked comparable denominator.
* Report safety findings, classifications, repeated work, interventions, and overhead without mapping unavailable rows to success/failure.

## Non-goals

* Modifying the comparator to add Elara receipt/recovery behavior.
* Substituting another runtime after target/comparator fault outcomes are exposed.
* Changing corpus rows, scores, thresholds, or eligibility from observed outcomes.
* Ranking languages, prompts, model quality, UI, or feature breadth.

## Acceptance criteria

* Comparator, adapter, inputs, and eligible rows match immutable reviewed commits/checksums.
* Every frozen row is marked comparable, not comparable, adapter failure, or not executed, with the locked reason preserved.
* If the floor is met, all eligible rows execute and only those rows contribute to comparative claims.
* If the floor is unmet, Result begins **Insufficient comparability** and contains no Elara-advantage/disadvantage claim from external evidence.
* No unavailable injection seam is scored.
* Any observation hook is disclosed and proven not to add recovery behavior.
* Report states whether external evidence supports, weakens, matches, or does not test the internal thesis, citing exact cuts and properties rather than runtime rhetoric.

## Verification

Run the immutable comparable subset and external runtime's own pinned checks:

```bash
mix test test/elara/benchmark/external_fault_run_test.exs --seed 0
mix elara.bench --manifest test/fixtures/benchmark/manifest.json --targets receipts,external --seed 0
mix test
mix format --check-formatted
mix compile --warnings-as-errors
```

Record the external runtime's documented build/test command verbatim. Re-run the scorer from raw evidence and verify report checksums. If the floor is unmet, run the report validator instead of fabricating fault rows.
