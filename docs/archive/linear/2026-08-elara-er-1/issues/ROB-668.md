## Description

## Outcome

Introduce an internal, controller-owned durable mutation identity and commit its intent before any executor dispatch. The operation digest must make accidental semantic reuse detectable and remain stable across controller restart.

## Context

The Flight Recorder already syncs a causal reducer effect before `Session` dispatches it, but its effect ID is currently discarded by both plugin and ordinary tool execution. The executor request carries model/tool-call identity and runtime metadata, but not a controller-owned durable job identity or operation digest.

Use the storage and ownership decision recorded in [ROB-667](https://linear.app/robert-guss/issue/ROB-667/fnd-1-freeze-the-er-1-contract-and-baseline-current-behavior). [ROB-772](https://linear.app/robert-guss/issue/ROB-772/fnd-2-preregister-evidence-thresholds-and-comparator-suitability) has frozen confirmatory evidence and comparator suitability before this target implementation begins. This is a prototype contract, not a public API or a BEAM-superiority claim.

## Scope

* Define the smallest internal job value needed by ER-1.
* Derive or allocate a stable `job_id` from controller-owned causal identity; do not trust the model-provided tool-call ID as the sole durable identity.
* Compute a versioned `operation_digest` over canonical:
  * operation kind;
  * tool name and version;
  * arguments;
  * workspace identity;
  * capabilities/authority relevant to acceptance;
  * any schema/version tag required to keep digest meaning stable.
* Persist an `intent` record and force the durability boundary before dispatch can occur.
* Load the same job identity and digest after controller/store restart.
* Add deterministic fault seams immediately before and after intent commit; production code must not use sleeps for crash ordering.

## Non-goals

* Executor acceptance or completion storage.
* Executing the marker mutation.
* Reconciliation or transcript changes.
* A generic workflow engine, outbox framework, Ecto domain layer, Mnesia, or distributed lease.
* Public stability for module names or persisted schemas.

## Acceptance criteria

* A committed job reloads with the same `job_id`, digest, state, workspace, and authority metadata after the owning process and storage connection restart.
* Equivalent canonical inputs produce the same digest independent of map insertion order.
* Changing tool version, arguments, workspace identity, or relevant authority data changes the digest.
* Dispatch is impossible until the intent transaction is durably committed.
* A crash before commit leaves no dispatchable job.
* A crash after commit leaves exactly one recoverable intent. Recovery submits or queries the same ID/digest under the frozen protocol; the intent alone never authorizes direct callback invocation, accepted-job failover, or a non-deduplicated mutation retry.
* Persisted schema and digest algorithm carry explicit versions.
* Existing nonmutating execution behavior remains unchanged.
* No change is made to `Elara.Session.Core` unless [ROB-667](https://linear.app/robert-guss/issue/ROB-667/fnd-1-freeze-the-er-1-contract-and-baseline-current-behavior)'s Result explicitly requires it.

## Result

### Outcome

It was fast-forward pushed to `origin/main`; no PR was used.

### Internal contract and schema

* Added `Elara.Effect.Job` as the controller-owned ER-1 value. `job_id` v1 is derived from the synced Flight Recorder identity `(recording_id, transition sequence, effect_index)`; the model tool-call ID is not part of durable identity.
* Added v1 SHA-256 `operation_digest` over deterministic external-term encoding of the frozen tuple: operation kind, tool name/version, canonical arguments, workspace ID, sorted required capabilities, authority scope (allowed capabilities + placement), and marker schema version.
* Added `Elara.Effect.ControllerJournal`, a direct Exqlite 0.40.0 sidecar with SQLite `user_version=1`, row-level schema/job-ID/digest versions, primary-key job identity, same-ID/different-digest rejection, WAL mode, and `synchronous=FULL`. No Ecto/domain layer was introduced.
* The Session shell lazily owns the journal. Mutating ordinary and plugin tool effects synchronously commit intent before task/executor dispatch. Nonmutating effects retain the direct path and do not open a journal.
* Persistent sessions place the sidecar beside their JSONL store. `persist: false` sessions lazily place mutation journals under the session root's `_effect_journals` directory so mutation dispatch still has a durable boundary; nonmutating sessions create no sidecar.
* Added only the frozen `:before_intent_commit` and `:after_intent_commit_before_dispatch` callback barriers. No sleeps establish ordering.
* No `Elara.Session.Core` change, executor acceptance/completion state, marker mutation, reconciliation, transcript policy, or public persisted-schema stability was added.

### Durability and ordering evidence

`test/elara/effect/job_test.exs` closes/kills the sole journal owner and reopens a fresh storage connection from the same path. It proves:

1. deterministic map/capability ordering and digest field sensitivity;
2. exact reload of job ID, digest, `:intent` state, workspace, capabilities, and authority metadata;
3. WAL / `synchronous=FULL` / schema-v1 settings and 0600 main-database mode;
4. idempotent same-ID/same-digest insertion and persistent same-ID/different-digest rejection;
5. process kill while blocked before COMMIT reopens with zero rows;
6. process kill while blocked after COMMIT reopens with exactly one intent;
7. no marker dispatch at either barrier, with a fresh reader observing the committed row at the post-commit/pre-dispatch cut; and
8. nonmutating Session execution invokes neither hook nor SQLite creation.
