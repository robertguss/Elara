## Description

## Outcome

Apply durable identity and reconciliation to the current single-file literal edit using ER2-1's exact shared vocabulary.

## Required states

Digest-bind path, exact transformation, expected preimage, desired postimage, workspace, and authority. Test exact preimage, exact postimage, neither, missing target, multiple matches, concurrent unrelated edit, terminal-reply loss, and ledger loss after mutation.

## Acceptance criteria

* Exact preimage permits one frozen original-owner execution; exact postimage is safe no-reapply but proves causal completion only with durable receipt.
* Neither image, multiple matches, and incompatible concurrent edits produce structured conflict/indeterminate outcomes without mutation.
* Same ID/digest never applies twice; changed operation under the same ID conflicts.
* Concurrent-change Result states preservation/conflict behavior and whether findings generalize beyond one literal file edit.
* Existing edit path remains available until GATE-2.

## Verification

Focused `patch_reconciliation_test.exs`, tools/executor tests, full suite, format, and warnings-as-errors compile. Result includes preimage/postimage/conflict and concurrent-change tables.

**Observed-state and safe-action table:**

| Durable/external evidence | Workspace observation | Result | Safe action |
| -- | -- | -- | -- |
| Exact preimage, one literal match | `expected_preimage` | One original-owner atomic replacement; terminal causal receipt on success | `none` after completion |
| Any source | `exact_postimage` | Postcondition is satisfied; current invocation performs no write | No reapply; causal completion only if a terminal receipt exists |
| Any source | Neither digest / incompatible concurrent bytes | Structured conflict; target preserved | `report_conflict` |
| Any source | Missing, non-file, or symlink | Structured rejection; no mutation | `report_rejection` |
| Exact preimage | Zero/multiple literal matches or computed postimage mismatch | Durable failed receipt; preimage preserved | `report_rejection` |
| Accepted receipt, callback count 0 | Exact preimage | Causality unproven, not invoked | Original owner may continue once |
| Accepted receipt, callback count 1 | Exact preimage | Causality unproven | Manual investigation, or cleanup of the exact job/digest-bound temp only |
| Accepted receipt, callback count 1 | Exact postimage | Causality unproven, callback invoked | `postcondition_satisfied_no_retry` |
| Controller-copied terminal receipt, executor ledger unavailable | Exact postimage | Causal `completed`/`failed` retained from receipt | Terminal action from receipt |
| No terminal receipt, executor ledger unavailable | Exact postimage | `indeterminate`; causal `unproven`, historical `unknown` | `postcondition_satisfied_no_retry` |
| Stale exact-postimage observation refreshed to conflict | Conflict | `indeterminate`; no retry | `refresh_then_report_conflict` |

**Concurrent-change and atomicity result:** The implementation snapshots and validates the exact UTF-8 preimage and unique match, materializes and digest-checks the complete postimage, writes a same-directory job-ID/digest-bound temp, refreshes the target precondition immediately before rename, and removes the bound temp after non-crash failures. A deterministic concurrent edit after temp completion was preserved and reported as conflict. A sampler observed only complete preimage or postimage bytes. This establishes atomic visibility and conflict preservation for the tested cooperative schedules. It does **not** claim filesystem durability across power loss (no directory/file fsync), causal completion from bytes alone, fencing against hostile OS-level path-component swaps, or exclusion of an external write in the final observation-to-rename interval.
