## Description

## Outcome

Apply the ER-1 job protocol to a declarative file write whose expected prior bytes and desired final bytes are digest-bound. Demonstrate when durable executor evidence proves this job completed, when independent bytes prove only postcondition_satisfied, and when conflicting or unavailable workspace state must remain explicit.

## Context

The current `write` tool directly creates parent directories and calls `File.write/2`; it has no precondition, postcondition, operation digest, or reconciliation behavior. This experiment treats the desired final bytes as a verifiable postcondition rather than treating a missing reply as the outcome.

Begin only if GATE-1 ([ROB-672](https://linear.app/robert-guss/issue/ROB-672/gate-1-decide-er-1-continue-pivot-narrow-or-stop)) records **Continue** at the scope needed for typed mutations.

## Scope

* Define a typed write operation containing path, expected-prior condition, desired content digest, and content/secure content reference required for execution.
* Bind the complete operation and workspace identity into the job digest.
* Define behavior for:
  * expected prior digest matches and write not yet applied;
  * target already equals desired digest;
  * target is absent when absence is expected;
  * target differs from both expected and desired;
  * partial/unreadable target;
  * executor completion survives but reply is lost;
  * executor ledger is lost after workspace mutation.
* Reuse the ER-1 controller/ledger protocol without weakening its identity rules.
* Record whether atomic replacement is required to avoid partial target states and implement only what the experiment needs.
* Preserve separate observations: executor completed requires durable causal receipt; exact desired bytes without receipt may establish postcondition_satisfied and a safe no-rewrite action, but not that this job executed/completed unless exclusive authority or fencing is proven.

## Non-goals

* General filesystem transactions.
* Directory trees, symlink traversal changes, permissions/ownership preservation beyond explicitly tested semantics, or binary delta transfer.
* Automatically overwriting conflicting workspace state.
* Public provider/tool-schema changes before GATE-2.
* Generic shell or patch reconciliation.

## Acceptance criteria

* Same job ID/digest never performs the write twice.
* Same job ID with changed path, expected digest, desired digest, workspace, or relevant authority is rejected as an identity conflict.
* A target already matching the desired digest is classified postcondition_satisfied and is not rewritten; it is classified executor completed only when durable causal receipt survives.
* A target matching the expected prior state can be executed only according to the accepted-job recovery rule selected at GATE-1; it never silently fails over to a different worker.
* A target differing from expected and desired is a structured conflict, not success or blind overwrite.
* Lost completion reply converges automatically when ledger completion survives.
* After ledger loss, exact declared bytes may establish postcondition_satisfied and the safe action not to rewrite, but causal job completion remains indeterminate without exclusive authority/fencing; any weaker observation remains indeterminate/conflicting.
* Tests cover absent, expected, already-applied, conflicting, and partial target states.
* Existing `write` behavior remains available until GATE-2 decides whether the typed protocol becomes canonical.
