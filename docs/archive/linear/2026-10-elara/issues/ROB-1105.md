No automatic approval, server-wire trust flag or model tool.
3. Explicit mix elara.trust command snapshots discovered source digests, lists paths/full-authority warning and prompts before saving approval; declined/EOF input saves nothing. Changed/new files require approval again. Trust is permission to execute local code, not sandboxing. Keep existing atomic file-write pattern and restricted directory/file modes; no approval framework or plugin generation redesign.

Public loader/session/reload test: compile-time side-effect witness remains absent until explicit approval, changed/new bytes fail while old loaded generation remains; approve exact snapshot then works. Trust-command decline and acceptance tests, actual native client new/list/reconnect check, cleanup assertions and guard-removal controls. Existing plugin fixtures approve only their own synthetic sources; ordinary transport fixtures include isolated synthetic token. No developer credentials/trust touched.
