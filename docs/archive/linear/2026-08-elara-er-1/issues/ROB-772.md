## Description

## Outcome

Preregister the confirmatory evidence design before any durable-effects implementation begins. Freeze how ER-3 tasks, fault rows, metrics, eligible narrower scopes, comparator evidence, thresholds, and amendments will be selected so later results cannot change the test.

## Context

[ROB-667](https://linear.app/robert-guss/issue/ROB-667/fnd-1-freeze-the-er-1-contract-and-baseline-current-behavior) freezes the technical ER-1 contract and current baseline. This issue freezes the later confirmatory research design before [ROB-668](https://linear.app/robert-guss/issue/ROB-668/er1-1-commit-stable-job-identity-digest-and-controller-intent) changes target behavior.

The core thesis is runtime-neutral durable-effect reconciliation implemented compatibly with BEAM process ownership. This preregistration does not claim BEAM superiority.

## Scope

### Sampling and exposure

* Commit an immutable candidate task pool or deterministic sampling frame, exact selection algorithm, and seed commitment.
* Define development, regression, and held-out exposure. A task inspected while designing the mechanism cannot later be represented as held out.
* Define conditional task/row selection for each possible GATE-2 scope without using observed target outcomes.
* Freeze 8–12 selected tasks that will produce 12–20 scored fault rows when the applicable GATE-2 outcome is known.
* Preregister strict eligible GATE-3 Narrow scopes and their deterministic selection order. Post-hoc task-level or row-level subsets are forbidden.

### Recovery metric

Each locked paired fault row receives one primary recovery classification. Let `B` be the number of paired baseline rows classified as ambiguous or requiring manual recovery, counting their union once, and `T` the corresponding target count over the same rows.

Freeze separate fields for bounded knowledge-state/safe-next-action convergence and terminal convergence. `completed`/`failed` requires admissible causal terminal evidence; `:indeterminate` may coexist with surviving intent, acceptance, callback-attempt, external-mutation, or noncausal postcondition evidence.

Material improvement requires both:

* `B - T >= 2`; and
* `(B - T) / B >= 0.50`.

If `B < 2`, material improvement cannot be established under this threshold.

Freeze the exact classification rubric, paired-row denominator, repetition count, aggregation, missing-row treatment, and report schema.

### Fixed product thresholds

The confirmatory design must preserve these project thresholds:

* zero duplicate external mutation, callback reinvocation without declared atomic ID/digest mutation deduplication, wrong/corrupt effect, false-success, false-error, or benchmark-contamination disqualifiers;
* 100% correct no-fault final workspaces;
* bounded truthful knowledge-state and safe-next-action convergence for 100% of rows, with `completed`/`failed` convergence for 100% of rows where preregistered admissible causal terminal evidence survives;
* no-fault timing: two unscored warmups plus 10 measured repetitions per row, aggregate by per-row medians; corpus median target/baseline ratio at most 1.20 and no row median ratio above 2.0;
* CPU and storage growth are reported but are not independent pass/fail gates in this experiment;
* dogfood: 8–12 planned tasks, at least 8 terminal classified outcomes, at least five supported failure types and two no-fault controls, zero safety disqualifiers, evidence-backed safe-next-action guidance for every injected failure, at least 80% of terminal tasks without unplanned recovery intervention, and no abandonment caused by protocol friction.

Freeze exact dogfood denominators and rounding before any run.

### External comparator

* Apply fixed suitability criteria: source available, immutable commit, local run, overlapping write/edit/shell semantics, deterministic provider injection, observable outcomes, and no required hosted control plane.
* Pin Lemon to one immutable commit and complete a source-backed suitability table. A replacement may be selected only for a preregistered suitability failure unrelated to comparative outcomes, using the same criteria.
* Freeze eligible operation classes and fault rows from capability and hook evidence before comparator or target fault outcomes are exposed.
* Comparative evidence requires no-fault equivalence for every included operation class and at least three equivalent fault rows spanning at least two fault types.
* If that floor cannot be met, the external result is **Insufficient comparability** and supports no comparative claim. External evidence remains secondary and does not alone block an internal Elara thesis decision.

### Amendments

Any amendment after relevant result exposure invalidates the confirmatory run. It requires a new preregistration version, new immutable inputs, and fresh held-out execution. Comparator replacement, task exclusion, threshold changes, and rubric changes must never reuse exposed confirmatory results.

## Non-goals

* Implementing the job protocol, benchmark runner, scorer, adapters, or fixtures.
* Running baseline, target, external, or dogfood fault rows.
* Selecting tasks because they favor observed ER-1 or ER-2 behavior.
* Treating unavailable external hooks as success or failure.
* Creating a repository roadmap document.

### Candidate frame and conditional branches

The immutable pool has 20 templates: 8 writes (W01–W08), 8 typed patches/edits (P01–P08), and 4 opaque shell tasks (S01–S04). Each has frozen primary/secondary externally alignable fault types F1–F4.

* Continue—Universal: 12 tasks / 20 scored fault rows.
* Narrow—Typed-only write+patch: 10 tasks / 20 rows.
* Narrow—Typed-only write only: 8 tasks / 16 rows.
* Narrow—Typed-only patch only: 8 tasks / 16 rows.
* Snapshot-dependent or Stop: no ER-3 materialization.

Selection is stratified by class and primary fault, then SHA-256 seed order. Every task contributes its primary row; lowest-key tasks add secondary rows until `R = min(20, 2*N)`. Each task also has a no-fault run. Fault repetitions are fixed at three per condition in a declared interleaving; inconsistent repeats are harness failure. Baseline target-only seams remain N/A/non-equivalent.

### Locked rubric, denominator, and thresholds

Every condition receives one primary class: automatic terminal, automatic known-nonterminal, automatic safe-indeterminate, manual recovery, ambiguous without a safe action, safety disqualifier, harness failure, or pre-exposure non-comparable. The bad-recovery predicate is the union of safe-indeterminate, manual, and ambiguous classes; mutually exclusive primary classes count the union once.

The denominator is every internal paired row accepted by [ROB-679](https://linear.app/robert-guss/issue/ROB-679/er3-2a-prove-baseline-and-receipt-adapter-equivalence) before fault exposure. Missing data, post-exposure exclusion, harness failure, or inconsistent repetition invalidates rather than shrinks it. `B` and `T` count bad baseline/target rows over that same set. Passage requires `B >= 2`, `B - T >= 2`, and exact `2*(B-T) >= B`.

Stop-first disqualifiers are duplicate external mutation, unprotected callback reinvocation, wrong/corrupt effect, false success/error, accepted-job failover, benchmark contamination, row substitution, or post-exposure tuning. Passage also requires 100% no-fault workspace correctness; bounded truthful knowledge/safe-action convergence on every row; causal terminal convergence whenever preregistered causal terminal proof survives; corpus median no-fault timing ratio <=1.20 with no row >2.0 after two warmups and 10 measured repetitions. CPU/storage are reported, not independent v1 gates. The artifact freezes every machine-readable row/report field.

Eligible strict GATE-3 Narrow scopes are, in order: N1 typed write+patch when shell is in full scope; N2 write only; N3 patch/edit only. Each must remain strict/nonempty and independently pass all applicable thresholds. No task/row/evidence-survival subset is eligible. Outcome precedence is safety Stop, full Continue, N1/N2/N3, then only three named Pivot contradictions, otherwise Stop.
