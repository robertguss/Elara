## Description

## Outcome

Use arbitrary `System.shell/2` execution as the negative control and establish the maximum truthful durability claim when command effects are opaque.

## Required states

Observe intent without acceptance, accepted/nonterminal, durable completed success/failure, lost completion reply, timeout, worker death, executor restart, ledger loss, and whether the child OS process is known terminated. Include a multi-resource or non-filesystem side effect that defeats simplistic file checks and one explicit typed-postcondition adapter seam.

## Acceptance criteria

* Surviving terminal receipt converges without rerun; same ID/digest cannot execute twice; changed command/cwd/env/workspace/authority conflicts.
* Missing terminal receipt after possible execution remains indeterminate. Command text and exit heuristics never upgrade it.
* Opaque work never silently retries on another owner.
* Typed postcondition evidence may establish current state/safe action but not causal completion without exclusive job-bound evidence.
* Result includes receipt × process-lifetime truth table and one-sentence maximum claim.

## Verification

Focused `opaque_shell_test.exs --seed 0`, executor tests, full suite, format, and warnings-as-errors compile.

**Receipt × process-lifetime truth table:**

| Durable evidence | External process observation | Causal / historical classification | Safe action |
| -- | -- | -- | -- |
| No controller intent | `not_spawned` | `not_started` / `not_invoked` | `new_job_id_allowed` |
| Intent, no admission | `not_spawned` | No execution proof | Same ID/digest/original owner may submit once |
| Accepted, callback count 0 | `not_spawned` | `unproven` / `not_invoked` | `original_owner_continue_once` |
| Accepted, callback count 1, no terminal | `alive`, `terminated`, or `unknown` | `unproven` / `invoked` | Never invoke again; adapter-exact → `postcondition_satisfied_no_retry`, otherwise `manual_investigation` |
| Completion wait timeout; controller copy still says attempt 0 | Observed `alive` | `unproven` / `unknown` until executor evidence is recovered | Never infer completion; adapter may refine no-retry action |
| Durable completed receipt | Independently reported; may be `terminated` or `unknown` | `completed` / `invoked`, session success | `none` |
| Durable failed receipt, including nonzero exit after mutation | Independently reported | `failed` / `invoked`, session error | `do_not_retry` |
| Controller-copied terminal receipt after executor-ledger loss | Independently reported | Terminal causal result retained | Terminal action from receipt; no rerun |
| Ledger unavailable, no terminal, adapter exact | Independently reported | `unproven` / `unknown`, session indeterminate | `postcondition_satisfied_no_retry` |
| Ledger unavailable, no adapter | Independently reported | `unproven` / `unknown`, session indeterminate | `manual_investigation` |

**Process-lifetime evidence:** The lifecycle fixture writes its exact shell PID, and a separate Linux `/proc/<pid>/stat` observer reports `alive`, `terminated`, or `unknown` without treating disappearance as completion. S1 observed a live PID before the effect; S2 observed exact adapter bytes while the shell was still live; S3 observed the exact PID terminated before callback return while the executor receipt remained nonterminal after the injected owner crash. During implementation, direct process-tree inspection also found that closing the BEAM-owned port/executor can terminate the recorded shell PID while an inner/orphan shell descendant remains alive. Tests therefore register and clean the observed process tree, and the runtime makes no descendant-termination claim. The final focused/full runs left no fixture shell processes behind.

**Typed adapter seam:** The only adapter is explicit `{"kind":"files_sha256","files":[...]}`. It validates workspace-relative non-symlink paths and freshly classifies each declared file. Exact hashes prove only current satisfaction and support `postcondition_satisfied_no_retry`; absent/conflicting/unavailable files and no-adapter jobs remain manual. A test command mutated both the declared primary file and an undeclared audit resource before exiting 9: the adapter matched, but the durable receipt correctly classified causal failure and forbade retry.

**Timeout behavior: **`Sidecar` no longer synchronously queries a busy executor after its completion wait expires. It returns source-qualified `indeterminate` from the controller copy; recovery of the executor ledger later exposes durable callback-attempt count one and still forbids rerun. The S-TIMEOUT test uses a 300 ms test-only completion-wait override while the digest-bound fixture value remains 5,000 ms, so the state machine is tested inside the frozen 5,000 ms convergence bound. This is an instrumentation acceleration and remains a deviation/uncertainty for the repeated [ROB-831](https://linear.app/robert-guss/issue/ROB-831/er2-4-execute-the-frozen-cross-class-failure-matrix) run; it does not alter command bytes or the resulting evidence semantics.

**Maximum truthful claim:** Elara can durably prove one admission and a shell's terminal success/failure when its receipt survives; after possible invocation without terminal evidence it can only refuse retry and optionally report a declared current postcondition—it cannot infer causal completion, safe replay, or descendant termination from command text, exit heuristics, file state, or process disappearance.

**Remaining uncertainty: **`System.shell/2`/port teardown does not provide a descendant process-group guarantee; inherited OS environment outside the explicit digest-bound fixture map is not controlled by this experiment; the adapter is observational rather than exclusive/fenced; and the accelerated timeout schedule must be reported distinctly in [ROB-831](https://linear.app/robert-guss/issue/ROB-831/er2-4-execute-the-frozen-cross-class-failure-matrix).
