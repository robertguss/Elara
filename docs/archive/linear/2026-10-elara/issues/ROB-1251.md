Acceptance:
1. Split call timing (always on in trace=profile runs; clock reads only, like ROB-1237). In `Profile.timed_census/1`, each `supervisors` reading gains `call_start` and `call_done`: monotonic ms immediately before and after the supervisor call itself, after `queue_before` is read and before `queue_after` is read. `Profiling.report` converts them to ms after t0, like the marks. `Profile.census/1` (untimed) is unchanged: the same calls in the same order, with no clock reads.
2. New integer concurrency param `session_sup_probe`, default 0, in `@defaults` (lib/elara/lab/scenarios/concurrency.ex:19). Only 0 and 1 are accepted; anything else raises ArgumentError in `params/1`, like the trace/topology checks. With 0, a run behaves exactly as at 06b8a65. The result line has no new keys. No new `Process.info` call, trace session, process or message happens. The only exception is acceptance 1's clock reads in profile runs.
3. Probe reading. One function, in a new small lab module (e.g. `Elara.Lab.SupProbe`, with a one-line moduledoc of authority and boundary), takes a target pid.
   - It spawns a short-lived process. That process records the clock in µs, makes one `Process.info(target, [:status, :current_function, :current_stacktrace, :message_queue_len, :messages])` call, records the clock again, classifies the messages and sends back only the summary, then exits. The mailbox copy therefore never stays on the sampler's or the coordinator's heap.
   - The caller starts the helper with `spawn_monitor` and returns after the helper's DOWN. A helper crash is an unavailable reading. If the helper has not finished within 5 s, the caller kills it and records the reading as unavailable.
   - The reading holds:
     - `read_us`: the Process.info call's duration;
     - `status`;
     - `current_function` as "Mod.fun/arity";
     - the top 4 stacktrace frames as "Mod.fun/arity" strings (no args, no locations);
     - `queue_len`;
     - `composition`;
     - `run_queue`: `:erlang.statistics(:total_run_queue_lengths_all)`, read in the caller next to the call.
   - `composition` counts messages by class, with no payload retained: `start_child`, `which_children`, `count_children`, `terminate_child`, `other_call` (any other `{:"$gen_call", _, _}`), `exit` (`{:EXIT, _, _}`) and `other`. Classification is a pure public function.
   - A dead or unregistered target gives an unavailable reading, never zeros.
4. Sampler probe. With `session_sup_probe=1`, the sampler (lib/elara/lab/sampler.ex) takes one probe reading of its target each tick (`sample_ms`, default 1000). The target is an optional start option, defaulting to `Elara.SessionSup`. All new sampler options are optional: existing callers (lab_sampler_test.exs:46, 72, 95) are unchanged. Each reading also records `t` (the tick's monotonic ms, reported as ms after t0) and `phase`, as the sampler's other readings.
5. Running trace. With `session_sup_probe=1`, at sampler start the sampler creates its own `:trace` session (`:trace.session_create/3`). The session's tracer is a lab process, and it sets `[:running, :monotonic_timestamp]` on the target only.
   The tracer aggregates `in`/`out` events into fixed buckets of `sample_ms` (bucket = div(event ms, sample_ms)). An on-CPU interval crossing a boundary is split across buckets. Each bucket holds:
   - `running_us`: the summed on-CPU time;
   - `ins`: the count of schedule-ins;
   - `outs`: the top 4 out-event MFAs as "Mod.fun/arity" with counts, plus an `other` count;
   - `off_us`: off-CPU time keyed by the MFA of the out-event that began it, for the top 4 MFAs by time plus `other`. Each off interval runs from an out-event to the next in-event and is split across bucket boundaries like `running_us`.
   Trace edges: an out-event with no preceding in (the target was running at install), or an interval still open at stop, is either dropped or closed at the stop time. The builder chooses, and the moduledoc states the choice.
   At sampler stop the session is destroyed and the buckets are returned with the samples. The session is also destroyed if the sampler is killed (the scenario kills it in a deferred cleanup, concurrency.ex:327): link the tracer, or have it monitor the sampler and destroy the session itself. A failed install records the trace as unavailable and does not fail the run.
6. Census probe. With `session_sup_probe=1` and `trace=profile`, the census's session_sup reading carries `probe`: a probe reading (acceptance 3), taken immediately BEFORE the `queue_before` read, plus `probe_elapsed_us` (caller-side clock before and after the whole probe: spawn, read, classify, reply). The order is probe, queue_before, call_start, call, call_done, queue_after, so the queue reads and the call keep their own brackets. Without the probe this field is absent. `Profile.timed_census/1` takes the target supervisor as an option, defaulting to `Elara.SessionSup`, for tests.
7. Start timing. With `session_sup_probe=1`, the sessions-topology user takes monotonic ms before and after each `Elara.start_session/1` call in `cycle/3` (concurrency.ex:652-667). It piggybacks them on the existing `{:session, sim_id, id}` report: no extra message per session.
