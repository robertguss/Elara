## Description

## Outcome

Apply the ER-1 job protocol to a declarative write whose path, expected-prior condition, desired bytes/digest, workspace, and authority are digest-bound.

## Required states

Test expected prior present, expected absence, exact desired bytes already present, conflict differing from expected and desired, partial/unreadable/non-file target, surviving terminal receipt with lost reply, and ledger loss after mutation. Decide and implement only the atomic replacement needed by the frozen contract.

## Acceptance criteria

* Same ID/digest never writes twice; any digest-bound field change under the same ID is rejected.
* Exact desired bytes are `postcondition_satisfied` and are not rewritten, but count as executor `completed` only with durable causal evidence.
* Expected state permits only the frozen original-owner action.
* Conflicting state is structured conflict, never blind overwrite.
* Lost terminal reply converges; ledger loss plus exact desired bytes yields safe no-rewrite but causal indeterminacy absent exclusive evidence.
* Tests cover every frozen state/cut and preserve existing write behavior outside the experiment path.

## Verification

Focused `write_reconciliation_test.exs`, existing tools/executor tests, full suite, format, and warnings-as-errors compile. Result includes the observed state/action table and atomicity boundary.

**Implemented operation and atomicity boundary**

* Exact `elara.declarative_write.v1` schema validation rejects unknown fields, mismatched desired digests, changed identity fields, invalid authority, absolute/traversal/noncanonical/NUL paths, symlink components/targets, and non-file targets.
* Expected absence or exact expected SHA-256 permits one original-owner callback. Exact desired bytes return a causal executor completion with zero primary target commits. Any other regular-file digest is structured conflict, never overwrite.
* Replacement creates/checks parents one component at a time, writes and verifies a uniquely job-ID/digest-bound temp file in the target directory, refreshes the precondition, then renames. Ordinary failure cleans its bound temp; process kill at the frozen T2 cut retains it for cleanup-only recovery.
* Atomicity claim is exact target preimage-or-postimage visibility for process crashes on the experiment filesystem. It excludes power-loss durability, directory transactions, and external-writer exclusion; no file/directory `fsync` is claimed.
* Ledger loss is an explicit unavailable-evidence path, never inferred from an empty replacement ledger. It re-observes before action and cannot submit/reinvoke. A controller-copied terminal receipt remains causal even after executor-store loss.

**Observed state/action table**

| Durable fact | Workspace observation | Causal/session result | Safe action |
| -- | -- | -- | -- |
| no intent | exact expected preimage | `not_started` | `new_job_id_allowed` |
| intent only or accepted attempt 0 | expected preimage/absence | one completed receipt and one target commit | same-ID original-owner submit/continue once |
| accepted attempt 1, no terminal | exact expected preimage | `unproven` / `indeterminate` | no retry; manual investigation |
| accepted attempt 1, temp retained | exact expected preimage | `unproven` / `indeterminate` | remove only the bound temp; no retry |
| accepted attempt 1, no terminal | exact postimage | `unproven` / `indeterminate` | `postcondition_satisfied_no_retry` |
| completed terminal receipt | exact postimage | causal `completed` | none |
| callback observes exact postimage before writing | exact postimage, zero primary commits | causal `completed` from its durable receipt | none |
| callback observes conflicting/partial/missing expected state | `conflict` or `absent` | causal `failed`, zero primary commits | report conflict/rejection |
| callback observes non-file/symlink/unreadable state | structured rejection/unavailable | causal `failed`, zero primary commits | report rejection |
| executor ledger known unavailable after mutation | exact postimage | historical `unknown`, causal `unproven`, `indeterminate` | `postcondition_satisfied_no_retry` |
| desired observation becomes conflict on mandatory refresh | conflict | causal `unproven`, `indeterminate` | `refresh_then_report_conflict` |
| terminal receipt copied to controller before ledger loss | current workspace reported independently | causal terminal result preserved | receipt-controlled action |

**Crash/control evidence**

* The focused test maps exactly to every frozen write row: W-C1…W-C8, W-T1/T2, no-fault, already desired, conflict, non-file, symlink, same digest, conflicting digest, replacement owner, ledger loss, and stale observation.
* C2–C5, C7, and C8 converge to one admission/attempt/terminal result and one primary commit. C6 retains attempt count 1, terminal count 0, one primary commit, and never reinvokes. T1 leaves no target/temp effect; T2 leaves the exact preimage plus one bound temp and permits cleanup only.
* Same-ID/same-digest replay adds no admission/callback/commit. Changes to schema, path, expected digest, desired content/digest, parent policy, replacement policy, workspace, or authority are digest conflicts. A replacement owner is rejected as `wrong_executor`.
* The atomic sampler observed only exact preimage or exact postimage while replacing a 1 MB target.

**Deviations and uncertainty**

* No frozen-row or semantic deviation and no post-exposure contract amendment. The generic Sidecar and existing public write/edit/bash paths are unchanged; this remains an internal experimental operation.
* Explicit executor-ledger unavailability must come from storage authority/operations; a newly empty ledger is intentionally not treated as proof that a prior ledger was lost.
* External writers can still race between the last observation and rename because v1 does not hold a workspace lease or use an OS-level compare-and-swap primitive. The frozen stale-observation recovery row detects refresh drift but does not claim global exclusion.
* Process-crash rename behavior passed on the current Linux experiment platform; power loss and other filesystems remain untested.
