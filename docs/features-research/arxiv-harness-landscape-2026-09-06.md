# arXiv harness landscape: context, memory, and tool interfaces

Research cutoff: **2026-09-06**. This shortlist complements the repository investigation in [Harness ideas for Elara](harness-ideas-beam-2026-09-06.md). It excludes the separate RLM/GEPA deep dives and the companion work on multiagent scaling and evaluation reliability. It is a selective reading list, not a claim of exhaustive coverage or a popularity ranking.

The strongest immediate candidates are versioned context updates, outcome-aware experience retrieval, and explicit operations on context views. The proposed Elara experiments below are our engineering hypotheses; these papers do not establish a BEAM advantage. Methods, experimental settings, results, and relevant limitations were read from primary paper text. No paper implementation was installed or executed, and reported results were not reproduced.

“Recent” and “established” mean different things here. CodeAct has an [ICML 2024 proceedings entry](https://proceedings.mlr.press/v235/wang24h.html), A-MEM has a [NeurIPS 2025 proceedings entry](https://proceedings.neurips.cc/paper_files/paper/2025/hash/19909c36f51abc4856b4560aff3d36d6-Abstract-Conference.html), and ACE's [arXiv record identifies ICLR 2026](https://arxiv.org/abs/2510.04618). Those are publication signals, not measured adoption or citation rankings. The August 2026 entry is a watch-list candidate because of its recency and mechanism; no popularity claim is made for it.

## What the papers actually support

**CodeAct: Executable Code Actions Elicit Better LLM Agents.** The useful mechanism is control and data flow: one action can call several tools, loop over results, and retain variables; execution errors feed the next interaction. Its M³ToolEval contains 82 hand-curated tasks with a ten-turn limit. For GPT-4-1106-preview, Table 3 reports 74.4% success with code, 52.4% with JSON, and 53.7% with text. Atomic API-call results are less decisive: several proprietary models prefer JSON. This supports testing compositional interfaces, not replacing every structured tool call or assuming the same gains with current models. The instruction-tuned CodeActAgent is a separate contribution from the off-the-shelf format comparison. [CodeAct v4, §§2–3](https://arxiv.org/html/2402.01030v4#S2)

**A-MEM: Agentic Memory for LLM Agents.** Notes retain interaction content and timestamps alongside generated keywords, tags, descriptions, embeddings, and links. Similarity selects neighbors; LLM calls decide links and evolve neighbors' descriptive attributes. This is richer than an append-only vector index. Experiments cover LoCoMo and DialSim; the main results describe stronger multi-hop performance but acknowledge GPT-based full-context/MemGPT advantages on some open-domain and adversarial categories. Retrieval settings also vary by category. For Elara, mutable derived knowledge is interesting, but replacing historical evidence with a generated interpretation would be an additional design choice, not a requirement of adopting linked notes. [A-MEM v11, §§3–4](https://arxiv.org/html/2502.12110v11#S3)

**A Survey of Context Engineering for Large Language Models.** Its formulation treats context as an assembly of instructions, knowledge, tools, memory, current state, and the immediate query, under a context-length constraint. The memory-management discussion distinguishes paging, hierarchical storage, and compression; the challenges section calls out unresolved composition and allocation questions. Use this as vocabulary and a map to original studies. Its breadth does not validate every technique it summarizes, and no performance gain is imported from its secondary descriptions here. [Survey v2, §§3.1, 4.3, 7.1](https://arxiv.org/html/2507.13334v2#S3.SS1)

**ACE: Agentic Context Engineering.** A Generator produces trajectories, a Reflector extracts lessons, and a Curator proposes local changes to identified playbook entries. A deterministic merge avoids asking the model to regenerate the whole accumulated document. Helpful/harmful counters and periodic deduplication manage growth. In Table 1, AppWorld's four-metric average rises from 42.4 for base ReAct to 59.4 for offline ACE with ground-truth feedback; this is not a single task-success metric. A no-ground-truth variant scores 57.2. The authors identify weak reflection and tasks needing only concise rules as limitations. Elara can borrow the update representation independently of deploying all three roles. [ACE v3, §§3–5](https://arxiv.org/html/2510.04618v3#S3)

**AgentFold: Long-Horizon Web Agents with Proactive Context Management.** Context retains invariant task information, summaries spanning contiguous history ranges, and the latest complete interaction. Folding can compress one step or consolidate a larger completed segment. The authors train a Qwen3-30B-A3B policy on filtered trajectories because prompting alone did not reliably produce the required behavior. They report 36.2% BrowseComp success; among surviving trajectories, average context grows from roughly 3.5k to 7k tokens over 100 turns. These are trained-policy observations with survivor conditioning, not proof of unlimited reliable operation. More than 20% of sampled tasks hit the 100-turn limit. [AgentFold v1, §§3–4](https://arxiv.org/html/2510.24699v1#S3)

**MemRL: Runtime Reinforcement Learning on Episodic Memory.** Memories contain intent, experience, and utility. Retrieval first enforces semantic relevance, then combines normalized similarity and utility; terminal rewards update utilities with a Monte Carlo rule while the backbone stays frozen. Table 2 reports held-out average success of 79.4% versus 76.6% for MemP across its selected transfer tasks and model configurations. Table 1's cumulative success across ten epochs answers a different question and must not be compared directly to one-shot success. Multiple retrieved memories make credit assignment ambiguous; low task similarity weakens cross-task benefit. This is useful evidence for outcome-linked memory, with a stronger requirement for trustworthy outcome signals than ordinary semantic search. [MemRL v2, §§4–6](https://arxiv.org/html/2601.03192v2#S4)

**SAGE: A Novelty Gate for Efficient Memory Evolution.** A density-based score over normalized embeddings resolves clearly novel and redundant candidates cheaply; uncertain cases use an LLM merge. Fact extraction still invokes an LLM. Including that shared extraction cost, the reported total write-call reduction is 29–42% on seven backbones, smaller than the routing-only reduction. A malformed-output baseline is excluded from that aggregate. All evaluation is English LoCoMo dialogue; the authors explicitly leave tool-oriented tasks, deletion, and compaction untested. Similar embeddings can still hide distinct facts. This suggests an admission-cost experiment, not proof that an embedding threshold safely discards arbitrary engineering evidence. [SAGE v2, §§3–4 and Limitations](https://arxiv.org/html/2605.30711v2#S3)

**Beyond Similarity: Trustworthy Memory Search for Personal AI Agents.** MemGate trains a roughly 9M-parameter network on 1,640 synthetic preference pairs, masking memory embedding dimensions conditioned on the query before reranking retrieved candidates. It does not rewrite individual offending sentences. For GPT-4o-mini, reported cross-domain failure drops from approximately 24.5–27% to 3–4% across evaluated memory systems. Sycophancy and tool-parameter errors remain. The transferable distinction is that a memory can resemble the query yet be inappropriate to apply. Its learned gate is neither a deterministic policy check nor an execution boundary. [MemGate v1, §§IV–V](https://arxiv.org/html/2606.06054v1#S4)

**AgenticRag-R1: Stack Memory for Multi-Step Reasoning, Retrieval and Memorizing.** This very recent study trains distinct planning, searching, summarizing, and backtracking actions over a last-in-first-out stack, with outcome/process rewards and rejection-based rollout selection. On the Qwen2.5-3B ablation, removing memory actions lowers reported average F1 from 33.55 to 27.37 across seven QA benchmarks. The intervention combines action design with training; it does not show that adding stack tools alone creates the same improvement. The authors identify computational overhead and hyperparameter sensitivity, and leave broader open-ended long-horizon work for later. Treat this as a mechanism to watch. [AgenticRag-R1 v1, §§2–3 and Limitations](https://arxiv.org/html/2608.29622v1#S2)

## Original Elara experiments suggested by the reading

These proposals build on the current reducer, persistent threads, flight recorder, context handoff, and Rust projections described in the [source-backed Elara inventory](harness-ideas-beam-2026-09-06.md#what-elara-already-has). They are not missing-feature assertions based on the papers. None starts the owner's deferred broad evaluation program.

**1. Give context changes the same explicit ownership as other runtime decisions.** Start with a small lesson store whose entries have durable IDs, supporting evidence, scope, and revision. A supervised advisory task proposes an addition or revision; the session validates its source cursor and generation before committing it. The Rust TUI can explain which entries entered the next request and which were rejected. Persist proposal outcomes separately from reconstructible indexes. A crash after proposal creation should neither lose an accepted change nor apply it twice. This exercises BEAM task lifetimes and single-owner state transitions around an ACE-like representation.

**2. Keep novelty, applicability, and demonstrated usefulness separate.** A lesson may be new but irrelevant, relevant but stale, or useful only for one tool version. Initially use explicit workspace, revision, instruction-scope, and tool-version checks, then compare candidate ranking with and without simple outcome counters. Outcome records should reference actual focused-check results, not the assistant's confidence. A small acceptance exercise can present a repeated failure, its confirmed repair, a similar failure in an incompatible revision, and a duplicated completion event. The desired behavior is scoped reuse and one accounting update per outcome. Concurrent helpers can propose evidence; one durable owner arbitrates revisions. Embedding work, if later needed, should have a bounded job queue and replaceable execution process.

**3. Let the agent revise its working view while retaining evidence.** Experiment with one range-addressed fold or retraction over a read-only research session. Preserve source-message IDs, unresolved constraints, and a retrieval path to material omitted from the next request. A later correction can supersede a fold; it does not erase the canonical trajectory or undo external effects. The acceptance exercise should recover an early source fact after several folds, reject a stale background candidate after steering, and resume with the same accepted projection after a process restart. This extends existing handoff provenance rather than requiring a new history model.

**4. Test a compositional read action at the existing Rust execution boundary.** Give one action a finite set of authorized read capabilities and explicit output, time, and call budgets. Ask it to inspect several files and return a compact structured result while retaining larger artifacts by reference. Compare the request sequence with ordinary calls on that same small task. Elixir owns the invocation lifecycle, capability generation, and cancellation; Rust remains useful for bounded native work and presentation. Generated executable code must not acquire authority merely by running in a BEAM process. Supervision provides lifecycle machinery; durable storage and OS isolation remain separate requirements.

The first two experiments have the clearest connection to persistent agent learning. The third tests whether continuity remains understandable when context becomes editable. The fourth asks whether a deeper tool interface reduces avoidable model interactions. The useful result is a concrete behavior Elara can demonstrate, together with its failure boundary, rather than adopting every paper's complete architecture.
