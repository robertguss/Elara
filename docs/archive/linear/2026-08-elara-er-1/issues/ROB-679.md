## Description

## Outcome

Build the minimum baseline-Elara and receipt-prototype adapters for the frozen neutral runner and prove no-fault semantic equivalence before any target fault result is exposed. This issue reviews adapter correctness only; the immutable paired fault run is [ROB-774](https://linear.app/robert-guss/issue/ROB-774/er3-2b-execute-the-frozen-baseline-versus-receipts-comparison).

## Context

[ROB-773](https://linear.app/robert-guss/issue/ROB-773/er3-1b-implement-the-neutral-benchmark-runner-and-scorer) supplies the reviewed target-neutral runner/scorer. The baseline is immutable commit `23e603550253c69846795b13cc2f2670f1122e21`; the receipt target is the immutable implementation accepted by GATE-2. Both receive equivalent scripted plans and isolated fixtures.

Adapter work must not add durable receipts to the baseline, remove receipts from the target, or expose confirmatory fault outcomes.

## Scope

* Build isolated adapters for baseline and receipt targets outside production semantics.
* Record full runtime, dependency, environment, tool, workspace, and storage configuration for both targets.
* Map every applicable frozen task/operation explicitly to each target.
* Prove fixture reset and initial digest before each no-fault run.
* Execute no-fault plans only and compare final workspace digest, expected tool/session observations, and harness evidence.
* Disclose baseline/target observation hooks and prove they do not add or remove recovery behavior.
* Mark each task semantically equivalent, non-equivalent, or adapter failure using frozen criteria.
* Fix adapter/harness defects only before any fault exposure; changes to frozen corpus/criteria require [ROB-772](https://linear.app/robert-guss/issue/ROB-772/fnd-2-preregister-evidence-thresholds-and-comparator-suitability) amendment rules.

## Non-goals

* Executing any fault row or calculating `B`/`T`.
* Tuning baseline or target behavior.
* Changing tasks, schedules, metrics, thresholds, or expected fault outcomes.
* Comparing external runtime or live dogfood.

## Acceptance criteria

* Both targets are identified by immutable commit and full runtime configuration.
* Every applicable task has an explicit adapter mapping and isolated storage/workspace.
* Every included no-fault task reaches the frozen correct final workspace on both targets.
* Initial and final digests, tool plan consumption, and expected observations are machine-readable.
* Any semantic non-equivalence or adapter failure is resolved under preregistered amendment rules before fault exposure or remains explicitly ineligible; it is never silently excluded later.
* Observation hooks are disclosed and proven behavior-neutral.
* No target fault result is produced, inspected, or scored.
* Result freezes adapter/report checksums consumed by [ROB-681](https://linear.app/robert-guss/issue/ROB-681/er3-4-dogfood-real-coding-tasks-with-scheduled-failures) and [ROB-774](https://linear.app/robert-guss/issue/ROB-774/er3-2b-execute-the-frozen-baseline-versus-receipts-comparison).
