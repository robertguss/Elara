### 2026-10-08T11:20:47.130Z — Robert Guss

## Plan (design first, subtract first)

**Reuse, not new mechanism.** Two tool structs in `lib/elara/tool.ex` next to `read`/`write`/`edit`/`bash` (`capabilities: ["filesystem:read"]`, `mutating: false`, version `1`). One new module `Elara.Tools.Search` holds both entry points. Workspace authority is `%Elara.Tool.Ctx{cwd: cwd}` — the same cwd ROB-1332 made authoritative — so `--cwd` needs no new wiring. Optional `path` scoping reuses `Elara.Effect.AtomicFile.target/2`, the existing lexical confinement rule (relative, canonical, no `..`, no NUL), rather than a second path checker. Execution reuses `Elara.Exec` with an argv (no `/bin/sh -c`), inheriting its process-group kill, timeout and byte cap.

**Two tools, not one.** `grep` (contents) and `glob` (names) take different arguments and return different shapes; one tool per verb matches the existing roster and keeps each JSON Schema tight. Both route through one internal module, so the parked "small roster with an intent argument" idea stays available later as a wrapper over that module — not revived here, not contradicted.

**Delegate to ripgrep; clear error when absent, no fallback matcher.** `rg` already provides gitignore semantics, binary detection and Unicode-aware regex. An Elixir fallback would mean a second approximate ignore engine, so the same tool call could answer differently on two hosts — the divergence hazard this repo's conventions warn about. So: single engine, and a missing `rg` is an actionable tool error naming the install. Both tools are advertised unconditionally, so the roster (and therefore prompts and FlightRecorder recordings) stays host-independent.

Pinned ripgrep flags: `--sort=path` for deterministic ordering, `--no-require-git` so `.gitignore` is honoured whether or not the workspace is a git checkout, `--hidden` with `-g '!.git' -g '!.hg' -g '!.svn' -g '!_build' -g '!deps' -g '!node_modules' -g '!target'` (exclusions last so they win), `--color=never`, `--max-columns` with preview, and `RIPGREP_CONFIG_PATH=""` so a user's `rg` config cannot change results.

**Bounded, read-only.** Result-count cap plus the existing stub byte cap, with one trailing truncation notice. Because nothing mutates, an interrupted, timed-out, capped or stub-lost search is an ordinary error or a labelled truncation — never `indeterminate`; there are no workspace bytes whose state is in doubt. Exit 1 is `no matches`; exit 2 returns ripgrep's own diagnostic as an error rather than presenting a partial scan as complete.

**Smallest diff:** `lib/elara/tools/search.ex` (new), two tool structs in `lib/elara/tool.ex`, one `summary` match arm in `native/elara-tui/src/tools.rs` so the compact header shows the pattern, README built-in-tools entries, and one scripted test file over disposable workspaces. No protocol, persistence, actor or instruction-preflight change: `instruction_preflight/3` stays scoped to `read`/`write`/`edit`, and reading a found file still goes through `read` with its guidance gate.
